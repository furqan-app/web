# Theming — Decisions

Active decisions for theming & design language — component library, theme architecture, accent system. Part of `docs/architecture/decisions/`; always-loaded index is [`../DECISIONS.md`](../DECISIONS.md).

---

## UI Component Library

**Status:** active

**Decision:** shadcn/ui (Radix primitives + Tailwind) for all new UI components. Lucide React for icons. Components are installed into `components/ui/` via `npx shadcn@latest add`.

**Constraints:**
- Do not install a separate icon library — use `lucide-react` only.
- Do not hand-roll components that have a shadcn equivalent.
- `DialogContent` (`components/ui/dialog.tsx`) supports an opt-in `hideDefaultClose` prop (default `false`) to suppress its built-in absolutely-positioned close button, for callers that need to render their own `DialogClose` in-flow (e.g. `MarkModal`, whose header needs the close button vertically centered against a flex sibling rather than absolutely positioned). Default behavior for all other callers (`SignInModal`) is unchanged.
- Every `DialogContent`/`SheetContent` (both wrap the same underlying `@radix-ui/react-dialog` primitive) **must** render a `DialogTitle`/`SheetTitle` — Radix hard-errors without one — and a `DialogDescription`/`SheetDescription` (or explicit `aria-describedby={undefined}` opt-out) to avoid a console warning. If the dialog already has a natural visible heading, promote it to `DialogTitle`/`SheetTitle` directly (its default classes are safely overridden via `cn()`'s `tailwind-merge`); otherwise add both as `sr-only`. See `docs/plans/fix-dialog-missing-description.md` for the fix across `MarkModal`, `SignInModal`, `Sidebar`, `SearchBar`, and `SettingsSidebar`.
- `components/ui/popover.tsx`'s `PopoverContent` takes an optional `container` prop (forwarded to `PopoverPrimitive.Portal`). **Always pass it, pointed at the enclosing `DialogContent`/`SheetContent`'s DOM node, whenever nesting a `Popover` (or `Command` combobox) inside a `Dialog`/`Sheet`.** Radix's Dialog `FocusScope` traps focus by DOM containment, not visual nesting — a `Popover.Content` portaled to the default `document.body` is a DOM sibling of the Dialog's own portal, so the Dialog keeps yanking focus back into itself on every keystroke, breaking typing and scroll inside the Popover. Fixed for `RecitationSettingsSheet`'s reciter combobox by capturing `SheetContent`'s node via a callback ref (`useState`, since a plain `useRef` wouldn't trigger a re-render once populated) and passing it as `container`. See `docs/plans/recitation-playback.md` Addendum 5b.

## Theme Architecture

**Status:** active

**Decision:** Named CSS palette classes (`.theme-light`, `.theme-dark`, etc.) on `<html>` define the full shadcn token set per theme. The `.dark` class is applied separately alongside the palette class to activate Tailwind's `dark:` utilities — so switching to dark mode means applying both `.theme-dark` and `.dark`. See [ADR 0003](../adr/0003-multi-theme-architecture.md).

**Constraints:**
- Always apply `.dark` together with any dark-variant theme class; never apply one without the other.
- The flash-prevention `<script>` in `layout.tsx` must mirror the class logic in `useTheme` — they share responsibility but cannot share code at runtime.
- `globals.css` must use `.theme-light` / `.theme-dark` selectors, not `:root` / `.dark`, for token definitions.
- No hardcoded color values anywhere outside theme class blocks in `globals.css`.

## Design Language

**Status:** active — reader-lab migration in progress

**Decision:** The app is migrating to the visual language proven in the Nocturnal Reader Lab, across all three themes and including the mushaf page face. The canonical design docs are rewritten **before** any token or component work. See [ADR 0047](../adr/0047-adopt-reader-lab-design-language.md) and `docs/plans/design-migration/INDEX.md`.

**Constraints:**
- **Two-accent grammar.** Gold carries identity, metadata and ornament; the primary accent carries live state only. This supersedes `design-principles.md`'s "never reach for a second accent colour" — do not re-apply the one-accent rule in review.
- The page face **may be lit**. ADR 0047 is the explicit decision that ADR 0032's "do not light the page face" required, and it supersedes ADR 0031's page-brightness rule too.
- Superseding an *aesthetic* decision is expected and must be recorded in the phase's plan. Superseding a *measurement of the medium* is not: dark's `(7,15,23)` headroom, pixel-sampled depth verification, WCAG AA pairs, and the mushaf no-overlap / line-rhythm / font-size invariants all carry forward unchanged.
- While the migration runs, `visual.spec.ts` snapshots are a **diff-review artifact, not a gate** — they are regenerated per phase. Every phase must therefore carry its own explicit mushaf-correctness verification; do not treat a green snapshot run as coverage.
- `design-principles.md` is canonical and generates root `DESIGN.md` via `/impeccable document`. Changing one without regenerating the other leaves the ADR 0041 review gate enforcing the superseded language.
- The reader lab stays an unlinked sandbox throughout and never ships; it gains light, gold and small-screen variants only as a derivation surface.
- **An atmospheric rule names a light source, never a channel.** Which channel expresses it — lightness or temperature — is decided per theme by measuring that medium's headroom, and so is the gradient's extent. Values derived for one theme measure zero when ported to another (ADR 0047 Addendum, Phase 0.1). Do not port; re-derive and sample.
- **The migrated brightness ladder is `creases < desk ≤ chrome < page face`** — the page is the brightest surface, superseding ADR 0031's deliberate inversion, because the lamp is on the paper. One order for all themes; the difference is values only (ADR 0047 Addendum, Phase 0.2). `--mushaf-text` is **not** part of the migration until a separate decision says so.
- **Never `shadow-[var(--token)]` in Tailwind.** It type-infers to a shadow *colour*, leaves `--tw-shadow` at `0 0 #0000`, and renders nothing while the class looks right in the markup. Use a named utility class (`.fq-panel-cast`) or `shadow-[shadow:var(--token)]`.
- **The focus ring's gap is `--chrome`, not `--background`.** The stock `ring-offset-background` pattern draws the gap in the page background colour, which is wrong on every dialog, sheet, popover, dropdown and nav bar. One shared `.fq-focus-ring` rule, not twelve per-component ones.
- **`animate-in` / `fade-in-*` / `zoom-in-*` / `slide-in-from-*` are inert** — `tailwindcss-animate` is not installed. Use `transition-*` on Radix `data-[state]`. Exit transitions will not play: Radix `Presence` defers unmount for CSS animations, not transitions.
- **Three theme blocks, not four.** `.theme-dark.dark` was byte-identical to `.theme-dark` across all 51 tokens and could never match without it, so it resolved to nothing while doubling every token edit. Removed in 2.1. `.dark` itself stays — Tailwind's `dark:` variant keys off it.
- **`--gold`/`--gold-muted` are the app-wide identity accent**, superseding ADR 0031's reader-only scoping and its per-theme aliasing. They had zero consumers before 2.1, so the scope change carried no visual risk. `--primary` is live state only, emerald in all three themes — including gold, whose warm `--primary` collapsed the two roles into one colour and measured 3.41:1 against its own foreground.
- **`globals.css` stays one file** (decided in 2.1, revisit after 5.1). Source order resolves `!important` ties throughout, and 0.3 shipped a real bug from exactly that; splitting reorders everything at once with no test that would catch a silent loss. The reader-lab block is ~1,050 of its lines and disappears when the lab is retired.
- **Three device classes: compact `<1024` (full-bleed, one page), spread `1024–1366` (full-bleed, facing pages), desk `≥1367×800`.** Production additionally splits `768–1023` into an inset single-page band; that is a CSS implementation detail, not a device class, and the migration overrides it. A portrait tablet gets the compact composition at full width. Production's bands are not a list of device classes — deferring to them reproduced a screen nobody had designed.
- **Atmosphere keys off whether a desk exists.** Lamp, vignette and nav arrows only exist in the desk band; below it the page is full-bleed and they would have nothing to act on. The page's own pool is unaffected everywhere, because it acts on the paper.
- **Chrome loses information as the viewport narrows; the mushaf never loses reading size** (ADR 0054). Below the desk band the rail relays into a bottom transport bar — reserving height, never width, so line length is untouched — and its physical-right placement is re-decided per band rather than inherited.
- **Page lighting belongs to the spread, not to a page.** Each card anchors the same pool to its own seam edge so the halves join at the gutter; one pool per card produces two pools and a bright seam.
- **Sample paper in the card's inner margin, never inside the text column** — a single pixel there lands on a glyph as often as on paper. For a ladder comparison use the page's lit body, not its shaded edge. And when comparing lab geometry to production, the line-rhythm invariant is **proportional**, not a constant offset: the lab's capped folio scales every gap, and an offset model reported a clean 0.86× scale as a rhythm defect.
- **The live accent is emerald in all three themes; only identity is theme-warm.** On the gold theme, `--primary` is itself gold, so reusing it for live state collapses the two-accent grammar into one. On light and gold, identity gold means a deep bronze that separates from the surface by lightness — a bright gold does not survive parchment.
- **App chrome is an opaque surface, never glass** (subtask 3.2, updated #413). `bg-background/75 backdrop-blur-md` over a `(7,15,23)` desk reads as a hole with the mushaf showing through, which is the entire reason dark needed `:root.theme-dark nav … { color: white !important }` on every descendant plus a counter-override to give the search dropdown its tokens back. `.fq-chrome-bar` supplies an opaque face and a top rim catch-light from one theme-agnostic rule (drop shadow / `--panel-cast` removed so it does not bleed onto the Mushaf page on mobile/overlay dismissal); all three overrides are deleted, and dark's nav text measures 15.39:1 on semantic tokens alone.
- **The brand mark is identity, so it is a medallion and not `--primary`.** `.fq-icon-chip` filled the logo with the state accent. `.fq-medallion` is a struck seal — gold rim, dark face — in **every** theme, which is also what keeps the white logo silhouette readable (design-language.md §12). The nav logo (`FurqanLogo`) uses a balanced 38px mark in a 40px footprint (`size-10`, #411), keeping it visible and prominent without overflowing the 56px bar height. The account avatar is identity too, and lost its `--accent` fill for the same reason; its unread dot keeps `--primary` and is the only accent on that control.
- **Three device classes, and production now matches them** (subtask 5.1c). The compact boundary is `1023`, not `767`: production's old `768–1023` inset band was a fourth screen nobody had designed, and the user rejected it on sight. `MOBILE_QUERY` in `use-is-mobile.ts` and every compact block in `globals.css` must stay numerically identical. **Known consequence:** reading size in that band moves 26px → 28px, because it now comes from compact's font-from-width cap instead of the desktop card clamp. Upward, and within ADR 0054's presets.
- **The desk carries a lamp and a vignette at the desk band** (subtask 5.1a), superseding the earlier "flat surround reads better" removal. Both objections it recorded are answered: the competing page gradient no longer exists, and the pool it was measured against had been derived for one theme. Measured lamp+vignette delta beside the folio vs the corner: light +11.4 L and **+18 warmth**, gold +14.5 L, dark +1.8 L. Light carries its lamp in temperature; the others in lightness.
- **Cap the folio one level below the stretch, never on the stretched box itself** (subtask 5.1a). Three arrangements were tried; two silently produced content height (654px) in every theme at every viewport size. `height: min(100%, …)` on the flex-grown column hits ADR 0036; `margin-block: auto` or `align-items: center` cancel `align-items: stretch` outright. Only capping `.fq-spread` *inside* the already-stretched column works, because by then the parent height is definite. None of the three failures is visible in the declaration.
- **The mushaf's page metadata, surah glyph and ornaments take the identity accent in every theme** (subtask 5.1b). Two theme-scoped blocks that forced them to `--mushaf-text` "so the info reads quietly, not gold" were deleted — the two-accent grammar reverses their purpose, and at `(0,4,0)` they outranked the theme-agnostic rule meant to replace them, so gold's surah glyph and all of dark's marks kept rendering as ink until they were gone.
- **The page pool anchors at the seam only when two facing pages are on screen** (subtask 5.1b) — the tablet band, and the desk band under `data-safha-view="double"`. A lone page has no gutter for the halves to join across, and anchoring it at one edge lights it from a seam that is not there.
- **The recitation transport is one markup in two compositions** (subtask 5.1d). Its three zones — identity, transport, utilities — are wrapped in `.fq-rail-zone`, which is `display: contents` everywhere except the desk band, where they become absolutely-positioned zones of a full-height 72px icons-only rail. The bar form is untouched by the wrappers. The transport pins to the rail's true midpoint, so it does not drift when the stop button appears with playback. `.fq-reader-spread-container` reserves `padding-right: 72px` for it — chrome reserves space, never overlaps the mushaf.
- **`.fq-chrome-bar` is declared late and wins ties by source order.** Any surface that opts into it and then needs a different face or shadow must raise specificity deliberately (e.g. `.fq-chrome-bar.fq-recitation-bar-rail`), not merely declare the override earlier. The rail's fade and `box-shadow: none` both sat in the file looking applied while the computed values were still chrome's opaque face and a horizontal bar's rim.
- **A geometry check over the reader must select per card, never per document.** The pager mounts three spreads side by side, so a flat `querySelectorAll` compares rows from off-screen panels against the first card's rectangle. That reported **374 escapes on a page that renders perfectly**. Same class of error as 0.1's wrong-`.fq-spread` probe.
- **Never name a new shared class without grepping the reader first** (found in 5.1, introduced in 4.1). `.fq-ornament` was already the mushaf's class for its header-band and footer markers; a new primitive of that name turned every one of them into a 58×10 hairline box — invisible on the four screens that introduced it, and only visible once the reader was opened. Renamed `.fq-rule-mark`.
- **`--warning` is its own token pair** (subtask 4.4), because neither accent may carry "something is wrong" and `--destructive` is too strong for a recoverable notice. It replaced the last raw `amber-*` utilities in the app, which shipped with a `dark:` variant — a per-theme fork of one rule. Contrast on a `bg-warning/10` surface must be measured against the **composited** fill, not the token: the first values passed inspection and measured 4.33 / 4.41 on light / gold, under AA.
- **`position: sticky` is trapped by an `overflow: hidden` ancestor** (subtask 4.1). `.fq-section-group` clips rows to its radius, which silently made a sticky heading stick to the group's own content box instead of the viewport — behaviour that worked before the migration. Use `.fq-section-group-open` where a group carries a sticky child.
- **A `//` comment between a Radix `asChild` trigger and its element is a text child, not a comment** (subtask 3.2). `Slot` throws `React.Children.only…` and the route dies. Inside JSX element children it must be `{/* … */}`; `//` is only valid inside an opening tag, between attributes.
- **Repetition gets hairlines, and a grid gets a lattice** (subtask 4.2). 114 surah cards is 114 competing objects, but a single-column hairline list of 114 rows scans worse than a six-column grid. `.fq-section-lattice` keeps the grid and paints its 1px gaps in the border colour — one surface, hairlines between entries — and degrades to exactly the hairline list at one column. Painted gaps, not per-cell borders: border arithmetic on a grid that reflows between 1 and 6 columns has to know which cells are on which edge at every breakpoint.
- **A chrome bar has exactly one live control, outside the well.** Secondary controls sit grouped in one `.fq-well`; the live one sits outside it and one step warmer. Measured separation is 12 / 8 / 12 lightness points on light / gold / dark, and the direction inverts with the medium — darker on light and gold, lighter on dark. Below `768px` the well drops its border and fill (`.fq-chrome-well`): its other members have already relocated into the account menu, and a lone icon in a pill outline is noise. The grouping is what sheds, never the control.

## Dark Theme Color Semantics: Gold vs Emerald

**Status:** active

**Decision:** In `.theme-dark`, gold (`--gold`/`--gold-muted`, plus the existing `--mushaf-ornament`/`--surah-frame-gold`) is confined to the reader page itself — ornaments, surah frames, verse markers, page decorations — with **no exceptions in chrome**. Emerald (`--primary`/`--accent`/`--ring`) covers every interactive element and every chrome surface, including ones referencing Mushaf content (the surah-list number badge is emerald). Never both on the same element. Revised from an earlier version of this decision that made the badge a gold exception — reviewing it rendered showed the two accents competing outside the page, which is the opposite of the goal. See [ADR 0031](../adr/0031-dark-theme-gold-emerald-semantics.md) and `docs/plans/dark-theme-mushaf-unification.md`.

**Constraints:**
- Before adding gold anywhere, the test is literal: is this element on the reader page itself? If not, it's emerald — no judgment call about how "Mushaf-identity-bearing" something feels.
- `--mushaf-paper` (the reader page background) is deliberately **not** the lightest step of the new 4-step background ramp — it sits one step above `--background` (app shell), not at the top. `--card`/`--popover` (drawers, dialogs, player) and a 4th "elevated" step for raised in-drawer chips sit above it. Do not "fix" the page to be the brightest surface — that was verified against the design reference and inverted on purpose (a real page under dim light is only slightly lighter than its surroundings, not glowing).
- Light and gold themes are unaffected by this pass — this decision and its token values apply to `.theme-dark`/`.theme-dark.dark` only.
- **`.theme-dark`'s `--accent-foreground` is deliberately NOT `--primary`, unlike every other theme** (2026-08-13, `docs/plans/home-page-design-fixes.md`). Same-day brand retint (`docs/plans/brand-mark-icons.md`) moved `--primary` to `169 88% 26%`, kept there specifically so `--primary-foreground`'s white-on-primary button text clears WCAG AA (5.09:1). That same 26% only measures 2.4:1 against `--accent`'s `161 58% 15%` background (the surah-list badge) — below the 4.5:1 floor, and no single `--primary` lightness satisfies both pairings (raising it enough to fix the badge drops the button-text contrast to ~2.7:1; darkening `--accent` toward black still can't clear 4.5:1 against a 26%-lightness foreground, max achievable is 4.12:1). `--accent-foreground` is `169 88% 39%` in dark theme only (measures 5.0:1 against `--accent`) — same hue, independent lightness. Do not "simplify" this back to mirroring `--primary` without re-deriving both contrast pairs; that regresses whichever one you didn't just check.
- ~~**Explicit exception (2026-08-19, user-requested):** the nav's surah-selector pill (`.fq-surah-toggle`, `app/globals.css`, `docs/plans/desktop-navbar-font-bg.md`) references `--mushaf-ornament` directly and keeps gold in dark theme's chrome, contradicting "no exceptions in chrome" above for this one control only. An intermediate `--nav-ornament` token that resolved to emerald on dark was tried and explicitly reverted by the user back to gold — do not reintroduce that token or re-derive an emerald variant for this element without a new request.~~ **Superseded by the Unified Accent System (2026-08-22) below:** `.fq-surah-toggle` no longer exists — it was replaced by `.fq-nav-ornament`, which references `--primary` (emerald) in every theme, including dark. `--mushaf-ornament` itself is now an emerald value in all three themes, so this exception has no gold left to protect.

## Unified Accent System: All Gold Accents and Ornaments Unified to Emerald Green

**Status:** active

**Decision (2026-08-22):** All gold accents, ornaments, overlines, badges, glyph tokens, and metadata across the entire app and all three themes (Light, Gold/Parchment, Dark) are unified to emerald green (`--primary` / theme-calibrated green scale). All `--gold`, `--gold-muted`, `--rl-gold`, and `--rl-gold-soft` CSS variables and Tailwind `colors.gold` are completely eliminated. `--mushaf-ornament` and `--mushaf-metadata` are set to rich emerald green values (`#13755a`/`#0f766e` light, `#116850`/`#0f766e` gold, `#10b981`/`#059669` dark). See `docs/plans/unify-accents-gold-to-green.md`.

**Rationale:** Simplifies the visual hierarchy into a clean, cohesive emerald green brand language while eliminating conflicting dual-accent competition across chrome and reader pages.

**Constraints:**
- Do not re-introduce `--gold`, `--gold-muted`, or `text-gold` / `border-gold` utilities.
- Use semantic tokens (`text-primary`, `border-primary/25`, `bg-primary/10`) for all accents, category overlines, and manuscript ornaments.
- Maintain WCAG AA contrast for text and metadata against paper backgrounds across all three themes.
