# 1.1 — Rewrite the canon

## Summary

Rewrite `docs/design/design-principles.md` to the new (reader-lab) language. This must land before any token or component work: migrating code against a stale canon means every subsequent phase is judged against the language being replaced.

## Approach

`design-principles.md` stated four rules the new language contradicts outright:

| Old rule | Replacement |
|---|---|
| "Never reach for a second accent colour; one is enough" — `text-primary` as the single unifying ornament | The two-accent grammar: gold for identity/metadata/ornament, primary for live state only |
| `◆` diamond separators as `text-[6px] text-primary` glyphs | Drawn ornament — hairline rules tapering to an open diamond, in gold |
| Navigation buttons `w-[52px] h-[52px]`, `bg-card border border-border shadow-sm` | The derived control geometry from `design-language.md` |
| Preferred shadow `0_2px_8px / 0_16px_48px-16px` | The shared depth ladder; dark carries lift with face-and-rim, not shadow |

Rewrite it as a distillation of `design-language.md` (0.4) — principles a reader applies, with the full derivation living in the language spec. Keep the sections still true (lucide-only icons, stroke weights, ornaments are `pointer-events-none` in a high z-index layer) rather than rewriting the file wholesale.

`DESIGN.md` (repo root) is **hand-maintained** — the `/impeccable` review gate and its `/impeccable document` generator were removed (`docs/plans/remove-workflow-skills.md`, #494). During this migration `DESIGN.md` carries a short hand-added banner at the top: it restates no design, edits nothing below it, points at the new canon, and tables the five old rules that must not be enforced. (When 1.1 was executed the plan called for `/impeccable document` regeneration — see Revision History for why that never ran.)

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| An old principle contradicts the new language | Replace it, and record the supersede in `Decisions Made`. |
| An old principle is orthogonal (icon library, stroke weight, pointer-events) | Keep verbatim. |
| A principle exists only in the lab and not in `design-language.md` | It was never derived. Do not add it here. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| A future task reads only `design-principles.md` | Can build a correct new-language component without seeing the lab. |
| `design-principles.md` after the rewrite | Contains no rule that contradicts the new language; keeps every still-true section. |
| `DESIGN.md` top banner | Present, non-substantive, points at the new canon, lists the five tabled rules. |

## Files to Change

- `docs/design/design-principles.md` — rewritten to the new language.
- `DESIGN.md` (repo root) — hand-added supersede banner at the top (nothing below it edited).
- `docs/standards/styling.md` — cross-reference to `design-language.md`; the token contract itself is updated in 2.1, not here.

## Constraints

- Must land before subtask 2.1 opens.
- Keep principles that remain true rather than rewriting the file wholesale — an unnecessary rewrite loses recorded reasoning.
- The `DESIGN.md` banner is non-substantive: it restates no design and edits nothing below it.
- No code changes in this subtask. Documentation only, so it is reviewable on its own.

## What NOT to Do

- Do not add principles that 0.4 did not derive.
- Do not delete the "Process" section pointing at `/frontend-design` — it stays, now grounded in the new language.
- Do not soften the accent-grammar rewrite to avoid conflicting with the old one. ADR 0047 already superseded it; a hedged canon leaves review ambiguous.
- Do not restate or edit any design below the `DESIGN.md` banner line.

## Decisions Made

- Canon before code — the design language leads the code by several migration phases.
- `DESIGN.md` carries a hand-added supersede banner for the duration of the migration. A stale canon was judged worse than one deliberate, non-substantive hand-edit.
- `styling.md`'s gold-aliasing rule is marked as migrating rather than rewritten — its token contract belongs to 2.1.
- The one-accent rule, the glyph separators, the 52px nav button geometry, and the preferred-shadow value are all superseded by ADR 0047.
- Documentation-only subtask, deliberately separate from 0.4, so the derivation and the canon rewrite are reviewed independently.

## Revision History

- 2026-08-21 — folded Addendum "the regeneration step could not run as written". The plan's "regenerate `DESIGN.md` via `/impeccable document`" step was impossible mid-migration: that command generates `DESIGN.md` *from project code*, which was still old-language, so it would have re-extracted the design being replaced. **Superseded the "`DESIGN.md` is generated, regenerate it, never hand-edit" constraint** — resolved with the user by hand-adding a short supersede banner at the top of `DESIGN.md`.
- 2026-09-02 (#494) — `/impeccable` and `/impeccable document` were removed entirely; `DESIGN.md` is now hand-maintained permanently, so the addendum's "regenerated properly once 2.1 lands" plan is also moot. Banner and hand-maintenance are the end state.
