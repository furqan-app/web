# Visual E2E Testing in the Workflow

> **Visual snapshot testing was deprecated and removed** (#428, 2026-08-27). `e2e/tests/visual.spec.ts`, all 36 baseline PNGs, `update-visual-baselines.yml`, and `visual-e2e-report-cleanup.yml` are deleted; `visual-e2e.yml` became `e2e.yml` running the **behavioral** Playwright E2E suites (`functional-e2e-*.md`, sibling issues #423–#427). The enduring output of this plan is the ephemeral e2e fixture-DB infrastructure, which those suites reuse.

## Summary

Built Playwright visual regression testing wired into a PR CI workflow: a committed full-dataset fixture DB let CI build and boot the real app without hitting the live QDC API, and 36 baseline images (5 screens × locale × theme × viewport) were diffed against committed baselines on every PR. High maintenance churn on benign styling changes, with no coverage of actual interactive journeys, led to its removal in favour of functional behavioral E2E. See [ADR 0022](../architecture/adr/0022-visual-e2e-testing.md) (including its deprecation addendum).

## Enduring infrastructure (still in use)

- **`e2e/fixtures/quran-fixture.sql`** — the committed **full 604-page** dataset (a trimmed fixture crashes `next build`, since `generateStaticParams` hardcodes all 604 pages and an out-of-fixture page's `pageMetadata.findUniqueOrThrow` finds no row). Regenerated only by running `npm run e2e:generate-fixture` (re-fetches all 604 pages from QDC — same cost as a full `seed:quran`); never hand-edited, so it stays a faithful derivative of the seeder logic.
- **`compose.e2e.yml`** — dedicated tmpfs-backed `quran-db-e2e` / `app-db-e2e` on ports **3309/3310** — never the dev DB ports 3307/3308 (`prisma db push --force-reset` would wipe the developer's real Quran DB).
- **`scripts/e2e-fixture/setup.js`** — `npm run e2e:setup`: force-resets schemas and loads the fixture SQL via `mysql2` (no `mysql` CLI dependency). Schema push only for `app-db` — this suite does not seed it.
- **`playwright.config.ts`** — desktop 1280×800 and mobile 390×844 projects, `testDir: e2e/tests`, `webServer` runs `npm run e2e:build && npm run e2e:start`. Screenshot config (`toHaveScreenshot` / `maxDiffPixelRatio`) and the JSON reporter were removed with the visual suite; standard `[["html", { open: "never" }]]` reporter.
- **`.github/workflows/e2e.yml`** (was `visual-e2e.yml`) — PR-triggered, read-only `contents: read`: checkout → Node → `npm ci` → MySQL service containers → `e2e:setup` → install Playwright chromium → `npm run e2e:test` → upload `playwright-report/` artifact on failure. Soft-blocking (not a merge gate).

## Constraints

- The fixture SQL must contain the **full 604-page dataset**; regenerate only via `npm run e2e:generate-fixture`, never hand-edit.
- E2E DBs use dedicated disposable containers on ports 3309/3310 — never dev DB ports 3307/3308.
- Do not seed `app-db` for the e2e build — schema push only.
- Do not modify `generateStaticParams` to derive its list from the DB — production code unchanged for a testing concern.
- PR CI soft-blocks on test failure via the Playwright report artifact upload.
- Do not modify `compose.e2e.yml`, `scripts/e2e-fixture/setup.js`, or `scripts/e2e-fixture/generate.js` when adding behavioral specs — the orchestration is shared and stable.

## What NOT to Do

- Do not re-add `toHaveScreenshot` visual snapshot comparisons, the 36 PNG baselines, or the `update-visual-baselines` / gh-pages diff-report machinery — deprecated for maintenance churn without journey coverage (#428).
- Do not keep `gh-pages` branch deployments for PR test runs — a standard artifact upload on failure is sufficient.
- Do not write new behavioral specs "in this plan" — they are partitioned into the `functional-e2e-*.md` plans / issues #423–#427.

## Decisions Made

- The fixture SQL duplicates the full output of the reproducible seeder (ADR 0022) — a committed derivative, regenerated by the generator, never hand-edited.
- Dedicated ephemeral e2e DB containers on 3309/3310, tmpfs-backed, force-reset per run.
- Visual snapshot testing is replaced by behavioral E2E (#428) — 36 PNG baselines and `toHaveScreenshot` gone; `visual-e2e.yml` → `e2e.yml` running the functional suites.

## Revision History

- 2026-07-15 — folded "Post visual diffs directly on the PR" (Trello #115): hosted the Playwright HTML report on GitHub Pages per PR at `reports/pr-<N>/` (additive push to `gh-pages`, never `actions/deploy-pages` which would clobber concurrent PRs) + a sticky PR comment keyed by a hidden marker; `visual-e2e-report-cleanup.yml` deleted a PR's report folder on close. (An `if:` condition needs a status function like `failure()` or GitHub Actions prepends `success() &&` and silently skips.) **All of this was later removed with the visual suite (#428).**
- 2026-07-16 — folded "Refresh fixture after the word-audio seeder fix" (Trello #116): regenerated `quran-fixture.sql` after PR #104 corrected `Word.audio_url` in `fetchVersesAndWords` — a data-consistency refresh, no baseline affected (`audio_url` isn't screenshotted).
- 2026-08-02 — folded "baseline PRs held at `action_required`": `update-visual-baselines.yml`'s `gh pr create` was opened as `github-actions[bot]`, which `approval_policy: first_time_contributors` gates. Fixed by using a member-owned fine-grained PAT (`secrets.FURQAN_ACTIONS_TOKEN`, `contents: write` + `pull-requests: write`) so the PR author is a repo member and the approval gate does not apply. **Workflow removed with the visual suite (#428).**
- 2026-08-02 — folded "opening-page flake": `visual.spec.ts` screenshot the reader without waiting for its client-hydrated line content, and `toHaveScreenshot` froze the loading skeleton's `animate-pulse` before its stability check, so a half-loaded page looked settled; `maxDiffPixelRatio: 0.02` was too loose for a mostly-uniform mushaf page to tell that from a real regression. Fix: a **positive** `waitForReaderContent` assertion (every mounted `.fq-quran-safha` has ≥1 `.fq-safha-row`, and ≥1 safha exists — never an absence-of-`.animate-pulse` check, which passes vacuously if the class is renamed), a positive search-results-heading wait (scoped to the searchbar under test — mobile mounts two `SearchQueryResults`), full baseline regeneration, and `maxDiffPixelRatio` → `0.002` sequenced as a separate PR (#175) after green runs against a known-good baseline. **Entire suite deprecated three weeks later (#428).**
- 2026-08-27 — folded Addendum "Deprecate Visual Snapshots & Transition CI to Functional E2E" (#428, epic #421). **Supersedes this whole plan's testing approach.** Deleted `visual.spec.ts` + 36 baselines + `update-visual-baselines.yml` + `visual-e2e-report-cleanup.yml`; renamed `visual-e2e.yml` → `e2e.yml` (name "E2E tests", read-only permissions) running `npm run e2e:test`; removed the screenshot config and JSON reporter from `playwright.config.ts`. The fixture DB infrastructure (`compose.e2e.yml`, `scripts/e2e-fixture/*`, `quran-fixture.sql`) stays — the behavioral suites reuse it.
