# Static Quran indexes from external APIs without DB

## Summary

Replace the MySQL-backed Quran static JSON generators with a single, DB-free build-time pipeline (`scripts/quran-static/generate.js`) that fetches directly from the QDC API into memory once, validates all 604 pages across all registered mushaf editions (`1`, `2`, `19`), reproduces the five existing client/reader JSON outputs byte-for-byte, and emits four compact server/service JSON indexes (`page-bounds/{mushafId}.json`, `rubs.json`, `verses.json`, `words.json`) to unblock DB-free cutovers (#749, #750), final `furqan_quran` retirement (#751), and the Epic #225 ASR alignment service without adding a single byte to mobile PWA or Capacitor precache/memory.

## Approach

Port the proven QDC fetchers, retry loops, `correctAudioUrl`, `validateLayout`, and metadata derivation logic from `scripts/quran-seed/` (`chapters.js`, `verses-words.js`, `mushaf-layout.js`, `derive.js`) into self-contained helpers inside `scripts/quran-static/generate.js` with zero `quranPrisma` or `QURAN_DATABASE_URL` dependency so `scripts/quran-seed/` can be retired cleanly in #751:

1. **Single QDC pass into memory:** Fetch `chapters`, all 604 pages of verses/words using `SEEDED_WORDS_MUSHAF_ID` (`2`), and the full word placement for each non-seeded edition in `LAYOUT_MUSHAF_IDS` (`1`, `19`) with `validateLayout` enforced on every edition.
2. **Pure in-memory derivation:** Build all 9 output families (5 existing + 4 new) from the validated in-memory dataset, keeping edition-scoped artifacts separated from riwayah-scoped artifacts per [ADR 0078](../architecture/adr/0078-static-quran-indexes-without-db.md).
3. **Byte-parity & atomic commit:** Support `--verify-existing` to compare generated bytes against already-committed `chapters.json`, `juz-starts.json`, `search-index.json`, `verse-pages/{mushafId}.json`, and `pages/{mushafId}/{page}.json`; write all targets via temporary files and atomic rename only after full validation succeeds, and support `--only=<target>` so legacy `npm run generate:quran-*` scripts delegate cleanly without hitting MySQL.

## Decision Tree / Algorithm

See [ADR 0078](../architecture/adr/0078-static-quran-indexes-without-db.md) for the architectural decision and client/server cache split.

| Output artifact | Client PWA Precache? | Scope | Exact schema / consumer contract |
|---|---|---|---|
| `public/quran/chapters.json` | Yes (existing ~14 KB) | Riwayah (Hafs) | Array of 114 `{ id, name_arabic, name_simple, verses_count, revelation_place, pages }` (`SurahResult[]`) |
| `public/quran/juz-starts.json` | On-demand (existing ~2 KB) | Riwayah (Hafs) | Array of 30 `{ juz, verse_key, defaultPage }` without trailing newline (byte-identical to committed file) |
| `public/quran/search-index.json` | Yes (existing ~0.5 MB gz) | Riwayah (Hafs) | Array of 6,236 `{ k, t, d, c }` rows matching ADR 0062 |
| `public/quran/pages/{mushafId}/{n}.json` | Opt-in edition download | Edition (`1, 2, 19`) | `{ lines, pageMetadata }` with deterministic `pageMetadata.id` offsets (`2→1..604`, `19→605..1208`, `1→1209..1812`) |
| `public/quran/verse-pages/{mushafId}.json` | Yes (existing ~72 KB/ed) | Edition (`1, 2, 19`) | `{ [verse_key]: page }` using the page holding the verse's first word |
| `public/quran/page-bounds/{mushafId}.json` | **No** (server only, ~97 KB/ed) | Edition (`1, 2, 19`) | `{ "1": { firstVerseKey, lastVerseKey, lastChapterId, verses }, ... }` for `/api/quran/pages/[pageId]/bounds` and `stop-point` |
| `public/quran/rubs.json` | **No** (server SSR only, ~367 KB) | Riwayah (Hafs) | Array of 240 `RubWithVerses`-compatible rows (`verse_mapping_start`/`verse_mapping_end` as integer `Verse.id`s, `rubVerseMappings`, `startVerse: { verse_key, page_number, Word }`, `endVerse: { verse_key, chapter_id, page_number }`) for `get-rubs.ts`, `/api/quran/juz/[juzNumber]/bounds`, `getRubPageRange` |
| `public/quran/verses.json` | **No** (server only, ~3.6 MB) | Riwayah (Hafs) | `{ [verse_key]: { id, verse_number, chapter_id, page_number, juz_number, hizb_number, rub_el_hizb_number, text_uthmani, words_uthmani_hafs } }` for `/api/quran/verses/[verseKey]`, `stop-point`, `/share/verse`, `resolve-units.ts`, `/api/marks` |
| `public/quran/words.json` | **No** (server + ASR only, ~4.4 MB) | Riwayah (Hafs) | `{ [location]: { u, h } }` for `char_type_name === "word"` (`u` = `text_uthmani`, `h` = `qpc_uthmani_hafs`) for `/api/marks` word enrichment and Epic #225 ASR |

Exact new output shapes (kept compact and strictly typed):

```json
// public/quran/page-bounds/{mushafId}.json entry
"120": { "firstVerseKey": "5:71", "lastVerseKey": "5:76", "lastChapterId": 5, "verses": ["5:71", "5:72", "5:73", "5:74", "5:75", "5:76"] }

// public/quran/verses.json entry
"1:1": {
  "id": 1, "verse_number": 1, "chapter_id": 1, "page_number": 1,
  "juz_number": 1, "hizb_number": 1, "rub_el_hizb_number": 1,
  "text_uthmani": "بِسْمِ ٱللَّهِ ٱلرَّحْمَـٰنِ ٱلرَّحِيمِ",
  "words_uthmani_hafs": "بِسۡمِ ٱللَّهِ ٱلرَّحۡمَٰنِ ٱلرَّحِيمِ"
}

// public/quran/words.json entry
"1:1:1": { "u": "بِسْمِ", "h": "بِسۡمِ" }
```

Pipeline execution rules:
- Fetch `chapters`, `verses + words` (`mushaf = SEEDED_WORDS_MUSHAF_ID`), and layouts for `LAYOUT_MUSHAF_IDS` completely before touching disk; abort immediately if any page fails retries or `validateLayout` rejects a page.
- Serialize every JSON file in memory first; in `--verify-existing` mode, compare bytes against existing committed files (`chapters.json`, `juz-starts.json`, `search-index.json`, `verse-pages/*.json`, `pages/*/*.json`) and fail loudly with the first differing path if any byte differs.
- Write each target file via two-phase staging (`<target>.tmp-<pid>-<n>`) before swapping any destination, rolling back swapped destinations and cleaning up temp files on failure.

## Verified Test Cases

| Case | Expected output |
|---|---|
| Divergent edition boundary — page 120 in mushaf `2` vs `19` (`5:77` starts page 121 in mushaf `2`, ends page 120 in mushaf `19`) | `verse-pages/2.json["5:77"] === 121` and `page-bounds/2.json["120"]` has `lastVerseKey: "5:76"`; `verse-pages/19.json["5:77"] === 120` and `page-bounds/19.json["120"]` has `lastVerseKey: "5:77"`; `pages/19/120.json` keeps `word.page_number: 121` on `5:77` words for canonical mark storage |
| Straddling verse across page break | `verse-pages/{mushafId}.json` maps the verse to the page of its FIRST word; `page-bounds/{mushafId}.json` includes the straddling `verse_key` in `firstVerseKey`/`lastVerseKey` and `verses` for both touching pages, matching current `mushafWordLayout` query semantics |
| Byte-for-byte parity on existing 5 asset families | Deterministic `pageMetadata.id` (`2→1..604`, `19→605..1208`, `1→1209..1812`), key ordering, and trailing-newline formatting match committed `chapters.json`, `juz-starts.json`, `search-index.json`, `verse-pages/*.json`, and all 1,812 `pages/*/*.json` files with zero byte differences |
| Transient QDC failure or validation error mid-run | Fetcher retries 3× with backoff; if exhausted or `validateLayout` throws, process exits non-zero without writing or leaving partial `.json` files in `public/quran/` |

## Constraints

- **Edition triple-sync (ADR 0033):** `GLYPH_FIELD_BY_MUSHAF` (`scripts/quran-seed/mushaf-layout.js`) and `MUSHAF_EDITIONS` (`app/utils/mushaf-editions.ts`) remain synced; glyph field, font, and layout travel together per edition.
- **Keep mushaf role constants distinct (ADR 0066):** `SEEDED_WORDS_MUSHAF_ID` (`2`), `DEFAULT_MUSHAF_ID`, `CANONICAL_PAGE_MUSHAF_ID`, and `PRECACHE_MUSHAF_ID` stay decoupled; only `SEEDED_WORDS_MUSHAF_ID` feeds `layoutFromSeededWords` and canonical `Word.page_number`.
- **Zero mobile precache/memory bloat:** Never add `page-bounds/*.json`, `rubs.json`, `verses.json`, or `words.json` to `globPublicPatterns` in `next.config.mjs` or `app/sw.ts`.
- **Zero DB dependency:** The new generator pipeline must run and pass verification with `QURAN_DATABASE_URL` unset and `quran-db` stopped.

## What NOT to Do

- Do NOT modify any `app/` runtime read paths (`get-page-words.ts`, `get-rubs.ts`, `app/api/quran/**`, `resolve-units.ts`, `use-search.ts`, `/api/marks`, `/share/verse`) in this issue — those cutovers belong to `#749` and `#750`.
- Do NOT delete `quranPrisma`, `prisma/quran/*`, `scripts/quran-seed/*`, or `compose.yml`'s `quran-db` service in this issue — that retirement belongs to `#751` after `#749` and `#750` land.
- Do NOT add `words.json`, `verses.json`, `rubs.json`, or `page-bounds/*.json` to `globPublicPatterns` in `next.config.mjs` or `app/sw.ts`.
- Do NOT drop per-page retries or write target files before full-book validation passes.

## Decisions Made

- **Single QDC pass + atomic writes over separate per-file scripts:** Fetching 604 pages × 3 editions once in memory prevents redundant QDC round-trips (~1,812 requests total instead of repeating per script) and guarantees cross-file consistency (`pages`, `verse-pages`, `page-bounds`, `rubs`, `verses`, `words` derive from one snapshot).
- **Server/ASR indexes stay out of mobile precache:** Client PWA and Capacitor devices already have `chapters.json`, `search-index.json`, `verse-pages/*.json`, and opt-in `pages/{mushafId}/{n}.json`; adding zero new client precached files preserves mobile RAM/Cache Storage budgets.
- **Edition vs riwayah boundary:** Keeping edition-keyed files under `{mushafId}` while isolating text/division indexes (`rubs`, `verses`, `words`, `chapters`, `juz-starts`, `search-index`) prepares cleanly for adding non-Hafs riwayat (Warsh, Qaloon) in future work without altering the reader contract.
- **Sweep check (step 3b):** Checked `vitest.config.ts` and existing references under `e2e/`, `app/`, and `.github/` — `vitest.config.ts` includes `scripts/**/*.test.mjs` (not `.test.ts`), so unit tests for the new generator must use `.test.mjs`; no existing unit or e2e test invokes `scripts/quran-*/generate.js` or asserts DB calls inside generator scripts. Verified `app/types/prisma.ts`, `app/api/marks/route.ts`, `app/api/quran/**`, `app/hooks/get-rubs.ts`, and `app/lib/plans/resolve-units.ts` directly to confirm every required field is covered by the four new JSON indexes.
