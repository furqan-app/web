# Replace placeholder logo with the Furqan brand mark (favicon, PWA icons, nav)

**Type:** feature
**Date:** 2026-08-13
**Status:** implemented

## Summary

Furqan currently ships a generic lucide `BookOpen`-in-navy-square placeholder as its identity everywhere: `public/icon.svg` (favicon), `public/icons/{icon-192,icon-512,icon-maskable-512}.png` (PWA manifest, generated from that SVG via `scripts/generate-pwa-icons.js`), and `app/components/nav/FurqanLogo.tsx` (in-app nav). This replaces all of it with the real Furqan brand mark — a manuscript-style mihrab niche with a ف letterform, emerald/gold/ivory — designed and critiqued this session (`/impeccable critique`, score 8/12, P0 legibility issue since fixed by the user's final export pass).

Final PNG assets, already generated by the user at every needed size, live at `/home/tahamohamed/Pictures/furqan-logo/`: `furqan-logo-512.png` (transparent bg, hero), `furqan-icon-192.png` (opaque light bg), `furqan-icon-maskable-512.png` (opaque light bg, full-bleed), `favicon.ico`, `favicon-16x16.png`, `favicon-32x32.png` (opaque emerald bg). This is a PNG-only swap — no more SVG hand-authoring; two earlier in-session attempts to hand-draw the mark as SVG produced bad results.

Trello card #204 ("Nav: fix logo/Continue Reading icon collision") already anticipated the nav half of this; scope was broadened via comment to cover favicon/manifest too. `ContinueReadingLink.tsx`'s separate BookOpen icon collision is explicitly **out of scope** — that's a distinct icon-choice decision, not a brand-mark swap.

## Approach

1. **Static assets**: copy the six PNGs from `/home/tahamongd/Pictures/furqan-logo/` into `public/icons/` (not `public/` root) under their existing target filenames, so the existing middleware/service-worker glob rules (which already whitelist `icons/**/*`) cover them with zero config changes. See Decision Tree below for exact filenames and why root placement was rejected.
2. **`app/layout.tsx` metadata**: update the `icons` block to reference the new files (drop `/icon.svg`, add favicon.ico/16/32 declarations).
3. **`app/manifest.ts`**: no code change needed — it already points at `/icons/icon-192.png`, `/icons/icon-512.png`, `/icons/icon-maskable-512.png` by filename; only the file contents change.
4. **`scripts/generate-pwa-icons.js`**: retire it (or leave as dead/unused — see Decisions Made) since icons are no longer generated from an SVG source at build/dev time.
5. **`public/icon.svg`**: delete — no longer referenced once step 2 lands.
6. **`app/components/nav/FurqanLogo.tsx`**: swap the lucide `BookOpen` icon for `furqan-logo-512.png` (the transparent-background hero export) rendered inside the existing `bg-primary` rounded-square container via `next/image`, keeping the container's theme-adaptive background so the mark still sits correctly across light/gold/dark themes.

## Decision Tree — asset placement

| File (source, `/home/tahamohamed/Pictures/furqan-logo/`) | Destination | Why |
|---|---|---|
| `furqan-icon-192.png` | `public/icons/icon-192.png` | Same filename already referenced by `app/manifest.ts` and `app/layout.tsx`'s `apple` icon entry — content-only swap |
| `furqan-logo-512.png` | `public/icons/icon-512.png` | Manifest `icon-512` entry — content-only swap. Transparent bg is fine here; manifest `purpose: "any"` icons are commonly composited by the OS |
| `furqan-icon-maskable-512.png` | `public/icons/icon-maskable-512.png` | **Blocked on re-export** — see Constraints. Content-only swap once received |
| `favicon.ico` | `public/icons/favicon.ico` | New file. Placed under `icons/` (not `public/` root) so it's covered by the existing matcher/glob whitelist for that directory — avoids editing `middleware.ts`'s regex or `next.config.mjs`'s `globPublicPatterns` |
| `favicon-16x16.png` | `public/icons/favicon-16.png` | Same reasoning |
| `favicon-32x32.png` | `public/icons/favicon-32.png` | Same reasoning |

**Why not `public/` root for the favicon files:** `middleware.ts`'s matcher regex names `icon\.svg` and `icons/*` explicitly (not a wildcard covering arbitrary root files); `next.config.mjs`'s `globPublicPatterns` is separately pinned to `['icon.svg', 'icons/**/*', 'quran/chapters.json']`. A new root-level `favicon.ico` would match neither, and would 404 behind the locale-redirect middleware exactly like the bug documented in `docs/plans/pwa-offline-support.md` Addendum 1 (see DECISIONS.md:118). Placing every new file under the existing `icons/` allowlist avoids touching either config file. Browsers that render the page always use the explicit `<link rel="icon">` tags Next's metadata API emits from `app/layout.tsx`; only legacy/blind `/favicon.ico` probing (some old crawlers, some bookmark UIs) would miss a root-relative fallback — accepted as out of scope for this pass.

## Verified Test Cases

- **Maskable safe-zone, measured concretely** (not eyeballed): `furqan-icon-maskable-512.png`'s glyph bounding-box corners sit ~265px from image center; Android's adaptive-icon safe-zone circle radius is 40% of 512 = ~205px. Corners are ~60px (12%) outside the safe circle — confirmed clipping risk on round/squircle-masked home-screen icons. User is re-exporting with more padding; this file is the one blocker before merge (see Constraints).
- **Nav icon background compatibility**: `furqan-logo-512.png` has a transparent background (verified: corner pixel alpha = 0), so it composites cleanly inside `FurqanLogo.tsx`'s existing `bg-primary` container across all three themes. `furqan-icon-192.png` and `furqan-icon-maskable-512.png` both have an opaque light background baked in (`#eef2f7`-ish) — confirmed unsuitable for the nav container, which is why only the 512 hero export is used there, not a scaled-down manifest icon.
- **Favicon-32 legibility**: rendered and visually reviewed this session — dome silhouette and ف hook stay legible at 32px, unlike the earlier hand-drawn attempt. Accepted as-is.
- **Favicon-16**: letterform is not legible (expected/accepted per the earlier critique — normal for any mark at 16px; only the color badge reads).

## Constraints

- Do not place any new favicon file at `public/` root — breaks the middleware/glob allowlist per the Decision Tree above.
- Do not merge with the current `furqan-icon-maskable-512.png` — the safe-zone measurement above is a confirmed defect, not a stylistic nitpick. Wait for the user's re-export.
- `FurqanLogo.tsx` must keep its theme-adaptive `bg-primary` container — do not bake a fixed background into the nav icon image itself (this is why the transparent 512 export is used there, not the opaque 192/maskable exports).
- `ContinueReadingLink.tsx`'s icon is untouched — out of scope (separate Trello concern).

## What NOT to Do

- Do not hand-author the mark as SVG again — two attempts this session produced bad results (webcam/eye-like glyph misreadings). PNG-only per the user's explicit decision.
- Do not fix the maskable safe-zone issue by programmatically scaling/recentering the existing PNG — the user chose external re-export over an auto-fix.
- Do not touch `middleware.ts` or `next.config.mjs`'s `globPublicPatterns` for this task — the `icons/`-directory placement choice exists specifically to avoid that.
- Do not update `ContinueReadingLink.tsx` — separate, not-yet-planned decision (its own Trello card note flags it needs a distinct "resume reading" icon, not a copy of the brand mark).

## Decisions Made

- PNG assets ship as-is (user-generated externally); no further SVG design work this task.
- Nav logo (`FurqanLogo.tsx`) is in scope for this task (user confirmed), `ContinueReadingLink.tsx` is not.
- Maskable icon safe-zone fix is a user re-export, not a programmatic auto-fix — implementation is blocked on receiving the corrected file before this can ship (open item below).
- New favicon files go under `public/icons/` rather than `public/` root, to stay inside the existing middleware/glob allowlist without editing either config file.
- `scripts/generate-pwa-icons.js` is deleted rather than kept dormant, since there is no longer a source SVG for it to regenerate from and a stale generator script would be misleading.
