# 4.3 — Search and settings surfaces

**Type:** feature
**Date:** 2026-08-21
**Status:** implemented
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Migrate the search overlay and its results, and the real settings surfaces — the settings sidebar's contents, the recitation settings sheet, and the offline recitation section. The lab built an inert mock of the settings inventory; this subtask replaces the real thing with the same structure, now with working controls and the states the lab never had to show.

## Approach

The lab's settings panel is the direct reference: grouped sections with gold overlines, hairline-separated rows, values stated as evidence rather than dressed as controls. What the lab did **not** have is live behaviour, and that is most of the work here:

- **Real switches, radios and sliders** with hover, press, focus, disabled and error states — the lab's were decorative.
- **Permission flows** (push notifications) with a genuine pending state and a denied state.
- **Offline recitation** with download progress, storage usage and failure — the most stateful surface in the app, and the one the lab's static mock most flattered.

Search is a different problem: an overlay with an input, a debounced result list, empty, loading and no-results states. The result list is the second place after home where repetition needs the language's answer.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| A settings row states a value and cannot change it | Value treatment, no control chrome — as in the lab. |
| A settings row is interactive | Real primitive from 3.1, with all states. |
| A row triggers a permission or download | Needs pending, success, denied and failure states designed. |
| A result row repeats | Grouped hairline rows, not cards. |
| An accent appears | State → `--primary`. Section overlines and metadata → identity. |
| A control is disabled | Must be distinguishable from inert-but-live-looking; the lab's `aria-disabled` mock is not the pattern for real controls. |

## Constraints

- Consume tokens and primitives; no colour literals.
- Do not change any settings *behaviour*, storage key, or permission flow — visual migration only.
- Search debounce timing and query normalisation are unchanged.
- Every interactive control needs a visible focus state that clears contrast in all three themes.
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not port the lab's inert mock as-is — these controls are real and need real states.
- Do not use `aria-disabled` on a genuinely disabled control; use native `disabled`.
- Do not redesign the settings information architecture; the lab already validated the inventory.
- Do not let the offline section ship with only its happy path designed.

## Decisions Made

- The lab's settings panel is the structural reference; its inertness is not.
- Control states — hover, press, focus, disabled, pending, error — are derived here and fed back into the language spec, since Phase 0 never covered them.

## Implementation notes (2026-08-22)

### Settings structure

Every setting was its own floating `p-4 rounded-lg bg-muted` slab under a muted `<h3>` — seven competing objects in one sheet. They now share `SettingsSection` (`app/components/settings/SettingsSection.tsx`): an identity overline introducing one grouped surface with hairline rows. Shared rather than repeated, so the sidebar's own blocks, the push toggle, the mushaf-layout picker and the offline section read as one inventory instead of four components' separate ideas of a section.

### Search gained three states it never had

The overlay rendered results and, otherwise, **literally nothing**. A typed query with no matches was indistinguishable from an empty box, and a slow query looked like a broken one. There are now four — idle, loading, no-results, results — sharing one `SearchState` shape so the overlay never restructures itself as the query changes, only its contents do. Keys added to both locales (`search.idleTitle`, `search.idleHint`, `search.loading`, `search.noResults`, `search.noResultsHint`).

Debounce timing (500ms) and query normalisation are untouched.

### The denied permission state, and the one behaviour-adjacent change

`usePushSubscription` tracked `supported`, `subscribed` and `loading`, but not the browser's permission verdict — so a **denied** permission made the switch flip and snap silently back with no explanation, forever, since re-requesting is a no-op once denied. The hook now also surfaces a read-only `permission` mirroring `Notification.permission`.

This is a read, not a flow change: `requestPermission()` is called in exactly the same place under exactly the same conditions, and its result is now recorded as well as branched on. The plan's "visual migration only" constraint is about not altering the permission flow, and it is not altered. The UI uses it for a native `disabled` (not `aria-disabled`, per the plan) plus a line telling the user where they can actually undo it.

Pending is expressed once, from the same `loading` that disables the control, so the row can never show two readings of itself at the same time.

### Accent-grammar corrections

| Element | Was | Now | Why |
|---|---|---|---|
| Recitation-sheet section icons (×4) | `text-primary` | `text-gold` | They say *what a section is* — identity. Selection ticks and selected options in the same file correctly keep `--primary` and were left alone. |
| Offline "downloaded" mark | `text-primary` | `text-gold` | Identity of the section, not a live state. |
| Language toggle, page-view toggle | `bg-background` / `bg-card` tray, `bg-accent` selection | recessed well tray, `--primary` selection | A segmented control *is* the well pattern: unselected members read as one dimmed group and the selected one is the only live thing on it. |
| Search result-group headings | `bg-muted` + `font-medium text-foreground` | overline register, `text-gold` | Same register as every other section heading in the app. |
| Unselected option surfaces, reciter rows | `hover:bg-accent` | `hover:bg-well` | `--accent` is the state accent's family; a hover is not a state. |

### Deleted literals

Three hardcoded `rgba` panel casts (`OfflineInstallPrompt`, `OfflineSetupGate`, `SearchQueryResults`'s `shadow-lg`) and every remaining `ring-offset-background` focus ring in this scope.

### Verified

- Settings sheet, light and dark, no page errors: overlines resolve to identity gold, each group is one surface, exactly one emerald selection per group.
- All four search states captured in both themes.
- Push denied state renders with the switch natively disabled and the explanatory line in place.

### A probe lesson worth keeping

Assigning `document.documentElement.className` to force a theme **does not hold**: `useTheme`'s effect owns that class list and reverts the assignment on its next run, so any screenshot taken after an interaction silently shows the stored theme instead of the requested one. The first settings capture came back light while claiming to be dark. Switch themes through the real control instead.

### Not done here

`MushafLayoutSection` still carries its own `<h3>` + `bg-muted` header and is visibly the odd one out in the sheet. It belongs to 4.4's file list and is fixed there.
