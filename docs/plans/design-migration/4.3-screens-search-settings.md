# 4.3 — Search and settings surfaces

**Type:** feature
**Date:** 2026-08-21
**Status:** ready-to-implement
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Migrate the search overlay and its results, and the real settings surfaces — the settings sidebar's contents, the recitation settings sheet, and the offline recitation section. The lab built an inert mock of the settings inventory; this subtask replaces the real thing with the same structure, now with working controls and the states the lab never had to show.

## Approach

The lab's settings panel is the direct reference: grouped sections with gold overlines, hairline-separated rows, values stated as evidence rather than dressed as controls. What the lab did **not** have is live behaviour, and that is most of the work here:

- **Real switches, radios and sliders** with hover, press, focus, disabled and error states — the lab's were decorative.
- **Permission flows** (push notifications) with a genuine pending state and a denied state.
- **Offline recitation** with download progress, storage usage and failure — the most stateful surface in the app, and the one the lab's static mock most flattered.

Search is a different problem: an overlay with an input, a debounced result list, empty, loading and no-results states. The result list is the second place after home where repetition needs the language's answer.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| A settings row states a value and cannot change it | Value treatment, no control chrome — as in the lab. |
| A settings row is interactive | Real primitive from 3.1, with all states. |
| A row triggers a permission or download | Needs pending, success, denied and failure states designed. |
| A result row repeats | Grouped hairline rows, not cards. |
| An accent appears | State → `--primary`. Section overlines and metadata → identity. |
| A control is disabled | Must be distinguishable from inert-but-live-looking; the lab's `aria-disabled` mock is not the pattern for real controls. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| Settings sidebar, three themes | New language; every category present and functional. |
| Theme switcher | Switches all three themes; selected state legible in each. |
| Font size control | Changes the reading size; the contract in ADR 0038 is unaffected. |
| Push notification toggle | Default, pending, granted and denied states all designed and reachable. |
| Offline recitation | Idle, downloading with progress, complete, and failed states all designed. |
| Search overlay | Opens, focuses the input, debounces (`fix-search-debounce-lag.md`), and closes on back gesture. |
| Search: empty, loading, no results, results | All four designed. |
| Search on desktop | Works — the regression in `fix-desktop-search.md` must not return. |
| Arabic query with hamza variants | Behaviour unchanged (ADR 0007). |

## Constraints

- Consume tokens and primitives; no colour literals.
- Do not change any settings *behaviour*, storage key, or permission flow — visual migration only.
- Search debounce timing and query normalisation are unchanged.
- Every interactive control needs a visible focus state that clears contrast in all three themes.
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not port the lab's inert mock as-is — these controls are real and need real states.
- Do not use `aria-disabled` on a genuinely disabled control; use native `disabled`.
- Do not redesign the settings information architecture; the lab already validated the inventory.
- Do not let the offline section ship with only its happy path designed.

## Decisions Made

- The lab's settings panel is the structural reference; its inertness is not.
- Control states — hover, press, focus, disabled, pending, error — are derived here and fed back into the language spec, since Phase 0 never covered them.
