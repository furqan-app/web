# 5.1 — Page face and reader

**Type:** feature
**Date:** 2026-08-21
**Status:** implemented
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Land the new language on the reader itself: the mushaf page face derived in 0.2, the reading stage and its atmosphere, the external page arrows, and the reader's own chrome. This goes last because it is where every remaining correctness invariant in the project lives, and because by this point the token layer, the primitives and the chrome have all been proven on lower-risk surfaces.

## Approach

Two distinct pieces of work, kept separate in the branch history so a regression can be bisected:

**(a) The stage.** Port the lab's composition to `/pages/[id]`: folio centring, the proportion cap, the lamp and vignette, the grounding cast, and the quiet page arrows. The lab already proved this exact composition against production reader components, so this is a port, not a derivation. The height chain is the known trap — `height: 100%` inside a flex-grown box resolves to `auto` (ADR 0036), which is precisely the bug the lab shipped with first.

**(b) The page face.** Land 0.2's mushaf token values into the four production theme blocks and the mushaf token family. This is the irreversible-feeling part: it changes how the Qur'an itself looks in every mode, at every breakpoint, in three themes, in both regular and tajweed rendering.

**(c) Collapse production's `768–1023px` band.** New scope, added by 0.3. Production splits that range into its own inset single-page treatment — desk margin, page arrows, one page — because its desktop margin starts at `≥1367` and `1024–1366` is deliberately full-bleed. The design recognises three device classes and the lab overrides that band to full-bleed compact; production must follow, or the shipped app keeps a screen the language does not describe. This touches `globals.css`'s `min-width: 768px` / `max-width: 1023px` rules, not just the lab's, so it is the one part of 5.1 that changes production layout rather than production colour.

The reader also has more layout modes than anywhere else: single and double Safha view, mobile carousel, tablet full-bleed, vertical pages, tajweed mode, shared-grant view, and the persistent pager (ADR 0028). Each is a separate verification pass.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| Height needs to travel below `.fq-reader-outer` | By `align-items: stretch`, never by `%` (ADR 0036). |
| A viewport-derived height is needed in the PWA path | Use the ICB-anchored fixed box, never `dvh`/`vh`/`svh`/`lvh` (ADR 0044). |
| Dark reader surface needs lift | Raised face plus warm rim. Never a shadow — `--reader-chrome-shadow` is `none` in dark by design. |
| A depth rule would be theme-scoped | Change values, not rules (ADR 0032). |
| Tablet band needs checking | `scripts/dev/reader-shot.mjs`; the MCP browser clamps at 1600px. |
| Any change would alter word placement, line count, or resolved font size | Stop. Correctness invariant, not an aesthetic. |
| Page arrows restyled | Must not enter, cover, dim, or clip Qur'an text. |

## Files to Change

- `app/globals.css` — reader stage, atmosphere, arrows, and the mushaf token family across all four theme blocks.
- `app/components/QuranSafha.tsx`, `QuranLine.tsx`, `QuranWord.tsx`, `QuranPage.tsx`

## Constraints

- Word placement, page dimension calculations, the font-size contract (ADR 0038) and the page font files are untouched.
- Never stretch the surah frame art; `height: auto`, width drives size, one colour role.
- Depth rules shared across themes; values differ.
- Verify by sampling rendered pixels, in all three themes, at every band.
- The reading size never shrinks to accommodate chrome.
- Land the stage and the page face as separate commits so a regression is bisectable.
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not use `height: 100%` below `.fq-reader-outer`.
- Do not use viewport units for the reader shell height.
- Do not add a drop shadow to a dark reader surface.
- Do not change `--mushaf-text` unless 0.2 explicitly decided to, with its own recorded reasoning.
- Do not let page arrows overlap Qur'an text.
- Do not treat a correct render at page 2 as evidence for 187 or 528.
- Do not rely on snapshots to catch an overlap or rhythm regression — they are regenerated, not gating.

## Decisions Made

- The reader goes last: every other surface has by then proven the tokens, primitives and chrome.
- Stage and page face land as separate commits for bisectability.
- The lab's composition is ported rather than re-derived, because it was proven against these exact production components.


## Implementation notes (2026-08-22)

Landed as three commits so a regression is bisectable: `5.1a` the stage, `5.1b` the page face, `5.1c` the band collapse.

### (a) The stage

**Two superseded aesthetic decisions, both recorded in place rather than quietly reversed.**

The desk pool had been added and then *removed* on review, with a comment saying "do not reintroduce it". Both of its objections are answered rather than ignored: the page gradient it was competing with was a centre-lighting ramp that no longer exists (the new pool is anchored at the **seam** and runs the other way, joining the lamp instead of fighting it), and "the flat surround reads better" was measured against a pool derived for one theme, before 0.1 established that a lamp's carrier channel belongs to the medium.

Trello #172's "leftover height becomes line gaps" is superseded **at the desk band only**. Below 1367px it is untouched, and it is still what makes the compact reader read like a printed mushaf.

**The folio cap took three attempts, and the first two failed silently.**

| Attempt | Measured | Why |
|---|---|---|
| `height: min(100%, --folio-max-h)` on `.fq-spread-col` | 654px — content height, in every theme, at every viewport height | The percentage resolved against a flex-grown container, i.e. `auto` (ADR 0036). |
| `max-height` + `margin-block: auto` on `.fq-spread-col` | 654px | An auto cross-axis margin cancels `align-items: stretch` outright. Same for `align-items: center` on the container. |
| Cap one level **down**, on `.fq-spread` inside the stretched column | 715px at 1440×900, **792px** at 1600×1100 | The column has a definite used height by then, so `100%` resolves against it. ADR 0036 is about indefinite parents. |

Neither failure is visible in the declaration. Both were caught by measuring the rendered box — reading the CSS would have passed all three.

**Measured desk atmosphere** (lamp+vignette delta, desk beside the folio vs the band corner):

| | light | gold | dark |
|---|---|---|---|
| lightness | +11.4 | +14.5 | +1.8 |
| warmth (R−B) | **+18** | −12 | −1 |

Light carries its lamp in **temperature** and its vignette in lightness, exactly as 0.1 derived; gold and dark carry the lamp in lightness. Dark's +1.8 is small by design — its lamp core is 0.075 — but it is not zero, which is the failure mode 0.1 caught.

At 1440×900 the band is 843px and the cap never binds, so that viewport is pixel-identical to pre-migration. The cap engages only on genuinely tall displays.

### A defect this subtask found in 4.1

**`.fq-ornament` was already the mushaf's class.** 4.1 introduced a `.fq-ornament` primitive for the drawn hairline-and-diamond; `QuranSafha.tsx` has used that same class name for the header-band and footer markers all along. 4.1's rule turned every one of them into a 58×10 hairline box — invisible on the four screens 4.1 touched, and only visible once the reader was opened.

Renamed to `.fq-rule-mark`, and its colour now comes from a `--fq-mark` custom property so a caller inside the mushaf can hand it `--mushaf-ornament` without the rule knowing anything about the reader.

### (b) The page face

0.2's derived values landed in the three production theme blocks: paper raised on gold (`#f7f0de` → `#fdf9ee`) and dark (`#0C1117` → `#111820`) so both clear chrome on the ladder, and ornament/metadata moved to the identity bronze in every theme. **`--mushaf-text` is untouched** — 0.2 explicitly declined to change the ink, and nothing here overrode that.

**Two theme-scoped blocks were deleted, and they were also outranking the fix.** Both the compact and the tablet band carried a `:root.theme-dark .fq-spread …` / `:root.theme-gold .fq-spread …` pair forcing page metadata, the surah glyph, the inline surah name and the ornaments to `--mushaf-text` so they would read "quietly, not gold". Ornament is identity under the two-accent grammar, so their entire purpose is reversed. They were also a per-theme copy of a rule the theme-agnostic block now states once — and at (0,4,0) against its (0,3,0) they won outright, so gold's surah glyph and every one of dark's marks kept rendering as ink until they were removed. Measuring caught that; the new rule looked correct in the file.

**The pool is anchored at the seam only where two facing pages are actually on screen** — the tablet band, and the desk band under `data-safha-view="double"`. Elsewhere a single page is showing, there is no gutter for the halves to join across, and the pool keeps its centred default. Anchoring a lone page at one edge would light it from a seam that is not there.

**Measured ladder** (`desk ≤ chrome < page`) at 1440×900:

| | desk | chrome | page | |
|---|---|---|---|---|
| light | 89.0 | 94.9 | 99.0 | OK |
| gold | 82.7 | 92.9 | 96.3 | OK |
| dark | 6.7 | 8.0 | 12.4 | OK |

Pool delta across the card (12% → 88% of width) at desk-double: 4.1 / 5.5 / 3.4.

**Two sampling rules had to be re-learned here**, both already in 0.4's verification notes: take the **max** lightness down a strip rather than a point sample (the first run reported light's page at L=67 — it had sampled the surah frame), and keep the strip away from the seam (the binding crease legitimately darkens the gutter, so a strip 10px in measures the crease and reports the gradient running backwards).

### (c) The 768–1023 band is gone

The compact boundary moved from 767 to 1023 across ten media queries in `globals.css` and in `MOBILE_QUERY`. The band's own 16px desk margin was deleted, its leg of the desktop card-width clamp was dropped, and page arrows are now CSS-gated out of compact — the JSX still carries `hidden md:flex`, which stopped matching the boundary once it moved.

`useIsMobile` widening is deliberate and its three consumers all read `isMobile || isTablet`: the nav overlay, the keep-screen-awake toggle, and its settings row. Those are precisely the compact behaviours §11 asks for.

### Verified

Word-overlap check (no two word boxes on a row may cross) run at **1440, 1200, 1023, 834, 768 and 390** in all three themes: **0 overlaps everywhere**. Resolved font size 26px at desk, 35.48px at tablet (auto-fit, unchanged), 28px across the new compact band, 24.9px at 390.

### One deviation from this plan, stated plainly

The plan required "reading size is unchanged by [the band's] removal". **It is not: at 768–1023 it moves from 26px to 28px.**

The band's size used to come from a *desktop* card-width clamp driven by the stored preset (default 26). It now comes from compact's own font-from-width formula, which at those widths is pinned to its 28px cap — the cap that exists precisely so portrait-tablet viewports do not render an oversized font (ADR 0011). 28px is one of ADR 0038's three presets, and the change is **upward**, so the constraint that actually matters — the reading size never shrinks to accommodate chrome — holds.

There is a second, narrower consequence: the desktop font-size control is `lg:`-gated and was already unreachable in this band, so a reader who chose 26 or 30 on a wide desktop and then narrows the window now sees 28. Ruling this out would mean giving compact a second font formula keyed to the desktop preset, which is a bigger change than the band collapse itself. Flagging rather than deciding it.

### Pages 1, 2, 187, 528 and 604

Run at 1440, 1200, 768 and 390, light and dark — 40 combinations. **0 word overlaps and 0 escapes from the card box** in every one, with the resolved font size constant per band (26 / 35.48 / 28 / 24.9).

The first version of this check reported **374 escapes on a page that renders perfectly**. It used a flat `querySelectorAll(".fq-spread .fq-safha-row")` and compared every row against the *first* card's rectangle — but the pager mounts three spreads side by side, so most of those rows belonged to off-screen neighbouring panels. Scoping each row to its own card is what makes the metric mean anything. Same class of error as 0.1's wrong-`.fq-spread` probe, and worth stating again: a geometry check over the pager must select per card, never per document.

### Not verified here

Tajweed rendering, the vertical-pages route, the shared-grant reader, slow-network page turns, and the installed-PWA fullscreen transition were not exercised — the first needs an edition switch and the rest need a device or a throttled session. Visual baselines still need the `workflow_dispatch` regeneration.
