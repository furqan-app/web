# 3.2 — Shared chrome

**Type:** feature
**Date:** 2026-08-21
**Status:** ready-to-implement
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Move the app-wide chrome to the new language: the navigation, the settings sidebar, the recitation player bar and rail, the search entry, and the notification bell. These are mounted globally, so they are visible on every route and set the app's first impression before any screen renders.

## Approach

The lab's navbar is the reference for the whole surface, and it demonstrated the two things production's chrome gets wrong today:

1. **The live control is indistinguishable from inert ones.** In the lab, three inert icons sit grouped in a dimmed well and the one working control sits outside it, brighter. Production's nav has the opposite: uniformly-weighted icons with no signal about which do anything.
2. **Identity and state share one accent.** The two-accent grammar separates them — the brand mark and orientation metadata become identity; playback, selection and live status keep `--primary`.

Files, in order: `nav/` → `SettingsSidebar` → `RecitationPlayerBar` (and its rail form) → `search/` → `notifications/`.

**Superseded in-flight work.** The uncommitted edits in `Nav.tsx`, `UserMenu.tsx`, `NotificationBell.tsx`, `SearchBar.tsx` and `RecitationPlayerBar.tsx` — shrunken icons (`md:size-3`), a removed `ReciterCombobox`, a restyled `.fq-nav-arrow` — are work-in-progress on #351 and #352, which this migration supersedes. **Default disposition is revert**, not reconcile: they are old-language treatments, and preserving them means designing the chrome twice.

Two exceptions worth reading before reverting wholesale:

- The **removed `ReciterCombobox`** is a feature deletion, not a restyle. Reverting restores reciter switching from the bar and the rail. If the new language wants that control elsewhere, decide it here deliberately rather than inheriting a deletion.
- #340 (in-review) and #346 (collapsible audio sidebar) carry *structural* intent — a navigation restructure and a new sidebar behaviour — not just a look. Absorb the intent where it survives contact with the language; discard the styling.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| A chrome control does something | Live treatment; `--primary` for its active state. |
| A chrome control is navigation or identity | Identity accent, or neutral. |
| Several inert or secondary controls sit together | Group them in a well; do not weight them individually. |
| The rail's layout declarations lose to a utility | Layout needs `!important` to beat JSX `inset-x-0`/`bottom-0`. Colour declarations a utility already sets will silently lose on source order — raise specificity deliberately or drop the declaration. |
| A dark chrome surface needs to read as raised | Opaque raised face plus warm rim. Never a shadow, never `bg-background/75` glass — neither lifts over `(7,15,23)`. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| Nav, three themes, both locales | Live controls visibly distinct from inert; no icon overflow (`fix-nav-icon-overflow.md`). |
| Nav overlay on tablet and mobile | Opens, closes, and navigates — the link-navigation race in `fix-nav-overlay-link-navigation-race.md` must not return. |
| Settings sidebar | Opens from every entry point that opens it today; closes on back gesture; no bottom clip. |
| Recitation bar, full-width form | Renders on production reader routes; reciter control present and working. |
| Recitation rail, ≥1367×800 | Screen-right, vertically centred, does not overlay the spread; no shadow in dark. |
| Desktop, tablet, mobile | Every control that exists at one breakpoint has equivalent access at the others — verified, not assumed. |

## Constraints

- Dispose of the superseded #351/#352 edits before starting — default revert; decide the `ReciterCombobox` removal explicitly.
- `UserMenu.tsx` imports `navPillClassName` unused — a lint error inherited from `main` at `1283e3a`, not introduced by this migration. Fix it here, since this subtask owns that file.
- Never add a drop shadow to dark chrome expecting lift.
- Rail layout declarations need `!important`; colour declarations must not rely on source order.
- Preserve every existing entry point: if a control moves, verify every breakpoint and route that reached it still can. A past plan removed an always-visible sidebar trigger and left desktop with no way to open it (`mobile-nav-ux.md` Addendum 3).
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not migrate on top of the undocumented working-tree drift.
- Do not remove or relocate a control without checking what depended on it.
- Do not restyle the reader's page arrows here — they belong to 5.1 with the reader.
- Do not weight every chrome icon equally; that is the problem being fixed.

## Decisions Made

- The lab navbar is the reference for the whole chrome surface.
- The two-accent grammar applies to chrome first, because chrome is where identity and state most often collide.
- Uncommitted chrome edits are reconciled as a precondition, not absorbed silently.
