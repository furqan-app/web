# 3.2 — Shared chrome

**Type:** feature
**Date:** 2026-08-21
**Status:** implemented
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Move the app-wide chrome to the new language: the navigation, the settings sidebar, the recitation player bar and rail, the search entry, and the notification bell. These are mounted globally, so they are visible on every route and set the app's first impression before any screen renders.

## Approach

The lab's navbar is the reference for the whole surface, and it demonstrated the two things production's chrome gets wrong today:

1. **The live control is indistinguishable from inert ones.** In the lab, three inert icons sit grouped in a dimmed well and the one working control sits outside it, brighter. Production's nav has the opposite: uniformly-weighted icons with no signal about which do anything.
2. **Identity and state share one accent.** The two-accent grammar separates them — the brand mark and orientation metadata become identity; playback, selection and live status keep `--primary`.

Files, in order: `nav/` → `SettingsSidebar` → `RecitationPlayerBar` (and its rail form) → `search/` → `notifications/`.

**Superseded in-flight work.** The uncommitted edits in `Nav.tsx`, `UserMenu.tsx`, `NotificationBell.tsx`, `SearchBar.tsx` and `RecitationPlayerBar.tsx` — shrunken icons (`md:size-3`), a removed `ReciterCombobox`, a restyled `.fq-nav-arrow` — are work-in-progress on #351 and #352, which this migration supersedes. **Default disposition is revert**, not reconcile: they are old-language treatments, and preserving them means designing the chrome twice.

Two exceptions worth reading before reverting wholesale:

- The **removed `ReciterCombobox`** is a feature deletion, not a restyle. Reverting restores reciter switching from the bar and the rail. If the new language wants that control elsewhere, decide it here deliberately rather than inheriting a deletion.
- #340 (in-review) and #346 (collapsible audio sidebar) carry *structural* intent — a navigation restructure and a new sidebar behaviour — not just a look. Absorb the intent where it survives contact with the language; discard the styling.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| A chrome control does something | Live treatment; `--primary` for its active state. |
| A chrome control is navigation or identity | Identity accent, or neutral. |
| Several inert or secondary controls sit together | Group them in a well; do not weight them individually. |
| The rail's layout declarations lose to a utility | Layout needs `!important` to beat JSX `inset-x-0`/`bottom-0`. Colour declarations a utility already sets will silently lose on source order — raise specificity deliberately or drop the declaration. |
| A dark chrome surface needs to read as raised | Opaque raised face plus warm rim. Never a shadow, never `bg-background/75` glass — neither lifts over `(7,15,23)`. |

## Constraints

- Dispose of the superseded #351/#352 edits before starting — default revert; decide the `ReciterCombobox` removal explicitly.
- Two lint errors are inherited from `main` at `1283e3a`, not introduced by this migration, and both files belong to this subtask: `UserMenu.tsx` imports `navPillClassName` unused, and `use-close-on-back-gesture.ts` has two `no-explicit-any` violations (lines 33 and 97). Fix them here.
- Never add a drop shadow to dark chrome expecting lift.
- Rail layout declarations need `!important`; colour declarations must not rely on source order.
- Preserve every existing entry point: if a control moves, verify every breakpoint and route that reached it still can. A past plan removed an always-visible sidebar trigger and left desktop with no way to open it (`mobile-nav-ux.md` Addendum 3).
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not migrate on top of the undocumented working-tree drift.
- Do not remove or relocate a control without checking what depended on it.
- Do not restyle the reader's page arrows here — they belong to 5.1 with the reader.
- Do not weight every chrome icon equally; that is the problem being fixed.

## Decisions Made

- The lab navbar is the reference for the whole chrome surface.
- The two-accent grammar applies to chrome first, because chrome is where identity and state most often collide.
- Uncommitted chrome edits are reconciled as a precondition, not absorbed silently.

## Implementation notes (2026-08-22)

**The superseded #351/#352 edits were disposed of by not porting them.** They exist only as uncommitted changes in the *main* working tree; this branch was cut from `main` at `1283e3a` and never carried them. Nothing was deleted from the user's working tree to achieve that — the default disposition (revert) is satisfied by the branch simply not having them. The main repo's uncommitted state is the user's to keep or discard.

**`ReciterCombobox` therefore survives.** The removal was part of that superseded work, so not porting it means reciter switching stays reachable from both the bar form and the rail form, exactly as on `main`. This is the conservative outcome: a feature deletion should be an explicit decision, and none was made.

### What the language actually changed

| Change | Why |
|---|---|
| `.fq-chrome-bar` replaces `bg-background/75 backdrop-blur-md` on the nav and the recitation bar | Glass over `(7,15,23)` is a hole, not a bar. Opaque face + top rim + cast, one rule, three token sets. |
| Deleted `:root.theme-dark nav … { color: white !important }` and its `.bg-popover` counter-override | Both existed only because chrome was translucent. Dark's nav text now measures **15.39:1** on `--foreground` alone, and the two-tier search-dropdown hierarchy the white override flattened comes back for free. |
| Deleted `:root.theme-dark .fq-recitation-bar-rail` face/rim and the rail's own `box-shadow` | Same reason — a theme-scoped copy of a rule the shared one now covers. |
| `.fq-medallion` replaces `.fq-icon-chip` on `FurqanLogo` | The mark is identity; `.fq-icon-chip` filled it with `--primary`, the state accent. The play button keeps `.fq-icon-chip`, because playback **is** state. |
| Nav's secondary controls (search, focus mode, notifications) grouped in one `.fq-well`; settings gear outside it as `.fq-chrome-btn-live` | The subtask's stated problem: uniformly-weighted icons with no signal about which of them act. |
| `.fq-chrome-well` drops the well's border and fill below `768px` | Its other members have already relocated into the account menu; a lone icon in a pill outline is noise. Chrome sheds the *grouping*, never the control. |
| Account avatar loses `bg-accent` / `text-accent-foreground` | `--accent` is the state accent's family, and the avatar is the one permanently-present element that is never live. Its unread dot keeps `--primary` and is now the only accent on it. |
| Juz/hizb separator `text-primary` → `text-gold` | Page metadata is identity. |
| `fq-focus-ring` on every chrome control | The search trigger had **no** focus style at all; the others used `ring-offset-background`, whose gap is drawn in the page background and so vanished on the bar. |

### Measured (rendered pixels, `/en/pages/2`, 1440×900)

| | light | gold | dark |
|---|---|---|---|
| desk L → chrome L (ladder `desk ≤ chrome`) | 95 → 95 ✓ | 87 → 93 ✓ | 7 → 8 ✓ |
| `backdrop-filter` | none | none | none |
| inert control contrast on chrome | 4.82 | 5.27 | 6.66 |
| live control contrast on chrome | 7.74 | 7.27 | 9.48 |
| live − inert, lightness | −12 | −8 | **+12** |
| surah orientation text on chrome | 14.00 | 13.77 | 15.39 |

The sign flip on the last row is the point, not a defect: raised is relative to the medium, so the live control is *darker* than its inert neighbours on light and gold and *lighter* on dark.

### One defect worth recording

A JSX `//` line comment placed **between** `<DropdownMenuTrigger asChild>` and its `<button>` is a text child, not a comment — Radix's `Slot` threw `React.Children.only expected to receive a single React element child` and the whole route died. `//` is only valid *inside* an opening tag, between attributes. Inside element children it must be `{/* … */}`. It rendered nothing visible in the source diff and only surfaced as a runtime error at one viewport.

### Not done here

- The settings sidebar's **contents** stay for 4.3, which owns the real control states. 3.2 would have restructured them and 4.3 would have restructured them again.
- Reader page arrows, the mushaf's footer diamonds and header-band marks still render in the state accent. They are ornament and belong to 5.1 with the reader.
