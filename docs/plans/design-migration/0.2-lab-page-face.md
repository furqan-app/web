# 0.2 — The mushaf page face in the lab

**Type:** feature
**Date:** 2026-08-21
**Status:** ready-to-implement
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Derive the new language for the mushaf page itself — paper, ink, ornaments, header band, footer, surah frame — inside the lab, in all three themes. The lab has so far rendered the page with production components untouched; this subtask is where the app's most important surface actually changes, and it happens where nothing depends on the answer.

## Approach

Add a lab-scoped page-face layer that overrides the mushaf token family (`--mushaf-paper`, `--mushaf-text`, `--mushaf-ornament`, `--mushaf-metadata`, `--mushaf-rim-*`, `--mushaf-sheet-*`, `--mushaf-crease*`, `--mushaf-page-cast`) under `.fq-reader-lab` only. Production values are untouched; this is a derivation surface.

Four questions to answer, in order:

1. **May the page be lit, and how much?** ADR 0047 lifts the prohibition. The lab's stage lamp currently falls *around* the folio; extending it *onto* the paper is the change. Too much and the page stops reading as print.
2. **Where does the page sit on the brightness ladder?** ADR 0031 deliberately made the page *not* the brightest surface. That is superseded, so the ladder is re-derived — but the ordering discipline stays: whatever order is chosen must be one order, shared across themes, with per-theme values.
3. **Ornament in the two-accent grammar.** The header band's `◆` glyphs and the corner stars currently use the single primary accent. Under the new grammar they are identity/metadata and become gold. The surah frame is the hard case: DECISIONS.md records it has exactly **one** colour role, and a previous three-role model needed per-theme overrides in two bands purely to collapse itself back to one. Keep it one role.
4. **Ink.** Whether `--mushaf-text` changes at all. Print black on lit paper is likely already correct; changing it is the highest-risk edit in the whole programme.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| Page lighting proposed | Sample rendered pixels at three themes before accepting. A gradient can be present and invisible. |
| Ladder order changes | Change it once, for all themes; express the difference in values. Never a per-theme rule. |
| Ornament colour role | Gold (identity/metadata). Surah frame keeps exactly one colour role. |
| Any change to line box, word placement, or font size | Out of scope — those are correctness invariants, not aesthetics. |
| Tajweed mode affected | Verify separately; tajweed scales font size 0.85×/0.88× and has its own per-theme block. |

## Verified Test Cases

Run every case in all three themes, and in both regular and tajweed mode:

| Page | Why it is in the set |
|---|---|
| 1 (al-Fātiḥah) | Short page, surah header, bismillah, maximum whitespace. |
| 2–3 spread | Dense body text, the reference case. |
| 187 | Long page, tightest line rhythm. |
| 528 | Multiple surah starts on one page. |
| 604 | Final page, short, two surah headers. |

Required outcome for each: no word overlaps another word, line rhythm is unchanged from production, the resolved font size is unchanged, and the surah frame renders at the correct ratio without stretching.

## Files to Change

- `app/globals.css` — lab-scoped mushaf token overrides and page-face treatment under `.fq-reader-lab` only.
- `app/components/reader-lab/` — a lab-local page-face wrapper if the treatment cannot be expressed in tokens alone. Production `QuranSafha` / `QuranLine` / `QuranWord` are **not** edited in this subtask.

## Constraints

- Lab-scoped only. No production mushaf token changes here; landing them is subtask 5.1.
- Never stretch the surah frame art to the line ratio — no `preserveAspectRatio="none"`, no viewBox widening. The frame renders at `height: auto` with width driving size.
- The frame keeps one colour role.
- Do not touch word placement, page dimension calculations, the font-size contract, or the page font files.
- Verify depth and lighting by sampling rendered pixels; use `scripts/dev/reader-shot.mjs` for the tablet band.

## What NOT to Do

- Do not change `--mushaf-text` without an explicit, separately recorded decision — ink is the highest-risk edit in the programme.
- Do not reintroduce a second or third colour role on the surah frame.
- Do not "simplify" the ladder by scoping it per theme.
- Do not treat a page rendering correctly at page 2 as evidence it renders correctly at 187 or 528.

## Decisions Made

- ADR 0047 supersedes ADR 0031's page-brightness rule and ADR 0032's "do not light the page face"; this subtask is where the replacement is derived.
- The ordering discipline of the depth ladder survives even though its specific order does not.
- Ornament moves to gold under the two-accent grammar; the surah frame's single-colour-role rule survives unchanged.
