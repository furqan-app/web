# 0.3 — Small-screen composition in the lab

**Type:** feature
**Date:** 2026-08-21
**Status:** implemented
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Design the mobile and tablet form of the language. The lab is desktop-only by construction — below 1367×800 it shows a notice, which is a guard, not a design. Every composition rule it proved (folio centring, the 72px right rail, the three-zone transport, the ornamented navbar) has no small-screen equivalent yet, and the production app's mobile and tablet reading modes are genuinely different layouts, not narrow desktops.

## Approach

Replace the lab's desktop gate with three real bands, keeping the notice only below a true minimum. The bands mirror production's existing reading contracts so the derivation transfers:

| Band | Production reading contract it must respect |
|---|---|
| Mobile (<768px) | One page at a time; font from width, `--fq-line-gap: 0`, gaps from flex `space-between` (ADR 0011). Nav is an overlay. |
| Tablet (1024–1366px) | Always a facing-page reader, **full-bleed** — `100dvh`, edge-to-edge cards, no drop shadows, nav as overlay. Explicitly not a desktop with margins. |
| Desktop (≥1367×800) | The composition already derived. |

Questions this subtask answers:

1. **Where does the recitation rail go** when there is no lateral whitespace to overlay? Tablet is full-bleed by decision; a 72px right rail would inset the book and shrink double-view text.
2. **What replaces the ornamented centre navbar** at 375px, where surah + juz + hizb + two ornaments cannot coexist.
3. **Does the folio proportion cap survive** on a full-bleed tablet, where the page is supposed to reach the edges.
4. **How the atmosphere reads** when the folio occupies ~100% of the viewport — a lamp and vignette need surrounding desk to fall on.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| Viewport is tablet band | Full-bleed, no shadows, nav overlay. Do not add desk margins to chase the desktop look. |
| Rail has no whitespace to overlay | Move the affordance; do not inset the book. Reserve no asymmetric width. |
| Atmosphere has no surround to fall on | Reduce or drop the layer for that band. A vignette with nothing to darken is noise. |
| Navbar metadata does not fit | Reduce information, not type size. Reading size is a contract, chrome is not. |
| Verifying tablet pixels | Use `scripts/dev/reader-shot.mjs`. The MCP browser clamps at 1600px and cannot reach the band. |

## Verified Test Cases

| Viewport | Required outcome |
|---|---|
| 375×812 | Single page, correct rhythm, chrome legible, no horizontal overflow. |
| 768×1024 | Portrait-tablet band renders its own stretch layout, not a squeezed desktop. |
| 1024×768 and 1366×768 | Facing pages, full-bleed, no shadows, no desk margin. |
| 1367×800 | Unchanged from the derived desktop composition — the band boundary is clean. |
| Any band, RTL and LTR | Composition mirrors correctly; the rail's physical-right exception is re-decided per band, not inherited by default. |

**Result — 14 combinations (7 viewports x 2 directions) pass.** Zero word overlaps, 15 rows, and no horizontal overflow at any size. Reading size identical to production in every band (375 → 23.88px, 768 → 26px, 1024/1366 → 29.97px, 1367 → 26px), so the reserve costs card height only.

| Viewport | Navbar | Transport | Pages | Desk atmosphere |
|---|---|---|---|---|
| 375x812 | 56px | 375x60 bar | 1 | off (full-bleed) |
| 768x1024 | 56px | 768x60 bar | 1 | **on** (121px margin each side) |
| 1024x768 | 56px | 1024x60 bar | 2 | off (full-bleed) |
| 1366x768 | 56px | 1366x60 bar | 2 | off (full-bleed) |

LTR is exercised by flipping direction on the live document: the lab route is deliberately `ar`-only (`locale !== "ar"` → `notFound`), and widening its scope is not something this subtask owns. Production is unaffected at every band — zero `fq-reader-lab*` elements on `/ar/pages/3`, nav and recitation bar intact.

## Findings

1. **Four reading contracts, not three.** The plan's band table omitted 768–1023px, which stretches the page but keeps a real desk margin. Building to the three-band table produced a wrong result there. Recorded in [ADR 0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md).
2. **Atmosphere keys off whether a desk exists**, using production's own full-bleed query verbatim rather than "below the desk band".
3. **The rail's physical-right placement does not survive the move** — a full-width bar has no side. The transport stays pinned to the bar's true midpoint, the same rule as on desk with one axis rotated; laying it out in flow let `space-between` push the primary control into a corner at 375px.
4. **The bar reserves 60px rather than overlaying** — a deliberate deviation from "tablet is 100dvh edge-to-edge", because chrome covering Qur'an lines defeats the reason edge-to-edge exists. Verified safe against ADR 0038 rather than assumed.
5. **Source order decided a correctness bug.** The compact band's `display: none` for the partner page sat above the desk band's `display: block`; at equal specificity and importance it silently lost, and 375px rendered two unreadable columns.

## Files to Change

- `app/components/reader-lab/ReaderLabDesktopGate.tsx` — becomes a band selector rather than a binary gate; the notice survives only below the true minimum.
- `app/components/reader-lab/ReaderLabShell.tsx`, `ReaderLabNavbar.tsx`, `ReaderLabRecitationRail.tsx` — band-aware compositions.
- `app/globals.css` — lab band rules, CSS-gated, still route-scoped.
- `messages/ar.json`, `messages/en.json` — any new copy.

## Constraints

- Band selection is CSS-gated, never UA detection or a JS breakpoint in the display path — it must be correct at first paint (ADR 0013 Addendum 4, ADR 0043).
- Tablet stays full-bleed with no drop shadows; this was an explicit user request recorded in DECISIONS.md.
- Do not reserve asymmetric width for the rail in any band.
- Do not change the reading size contract at any band to make chrome fit.
- Lab-scoped only; production reader layout is untouched.
- Band rules key off whether a **surround exists**, not off a breakpoint number. Use production's full-bleed query — `(max-width: 767px), (min-width: 1024px) and (max-width: 1366px)` — for anything that acts on the desk.
- Place order-dependent `!important` overrides deliberately. Two rules at equal specificity are resolved by source order, and grouping by topic instead put a band override above the rule it was meant to beat.

## What NOT to Do

- Do not port the desktop surround to tablet by insetting the book — it costs reading area and shrinks double-view text.
- Do not use `dvh`/`vh` for the lab shell height in the installed-PWA path; viewport units go stale across the fullscreen transition (ADR 0044).
- Do not build a mobile design that assumes hover.
- Do not keep an atmospheric layer in a band where it has no surface to act on.

## Decisions Made

- The rail's physical-right placement is a desktop decision and is re-decided per band rather than inherited.
- Chrome loses information before the mushaf loses reading size. Dropped in order: ornaments (<1367), wordmark + lab badge + inert well (<1024), juz/hizb + the rail's five tertiary utilities (<768). The identity medallion and the one live control survive every band.
- The notice fires only below `max-height: 400px` — a viewport too short for a 15-line page, where there is nothing to compose rather than something to compose differently.
- The transport bar reserves height instead of overlaying, trading the vertical edge-to-edge for never covering a Qur'an line. Reading size was measured against production in every band to confirm the trade costs nothing that is under contract.
- The lab route stays `ar`-only. LTR is verified by flipping direction, not by opening the route.
