# 4.4 — Mushaf hub and shared-grant surfaces

## Summary

Migrate `/mushaf` (the hub) and the shared-grant surfaces at `/mushaf/[grant]/pages/[id]` — the layout guard's redirect states, the "viewing someone else's mushaf" chrome, and the access-removed banner. Also the mushaf-layout selection UI, which is where a user picks a print edition.

## Approach

This screen carries two things the rest of the app does not:

1. **A borrowed-context state.** When viewing another user's mushaf, the app must say so persistently without competing with the reading surface. Under the two-accent grammar this is *identity* information — whose mushaf this is — which is exactly the role gold now carries. That makes this the cleanest demonstration of why the language needed two accents.
2. **Privacy-constrained copy.** ADR 0012 forbids showing the owner's name on the access-removed path; the banner is deliberately generic. The visual treatment must not imply more identity than the copy is allowed to carry.

The mushaf-layout picker is a selection surface over print editions and is likely to gain more options later — the schema was kept generic for exactly that. Design it to hold more than two entries.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| Element states whose mushaf is being viewed | Identity accent. |
| Element states a live/selected edition | `--primary`. |
| Access was removed | Generic banner; no owner name, no identity treatment implying one (ADR 0012). |
| Layout picker gains entries | Must hold more than two without redesign. |
| An unauthenticated or revoked user arrives | `redirect()`, not `notFound()` — behaviour unchanged. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| `/mushaf` hub, three themes, both locales | New language; edition picker legible and holds >2 entries. |
| Viewing a granted mushaf | Borrowed-context chrome present and persistent, not competing with the page. |
| Access revoked → `/mushaf?removed=1` | Generic banner, no owner name, correct redirect. |
| Unauthenticated on a grant route | Redirects to locale home. |
| Root 404 | Still uses theme tokens and plain `<a>` links — a `next/link` client-nav from the root 404 can paint before the locale tree's CSS chunk loads in prod. |
| Mobile, tablet, desktop | Hub composition holds at every band. |

## Files to Change

- `app/[locale]/mushaf/page.tsx`
- `app/[locale]/mushaf/[grant]/pages/[id]/page.tsx` and its layout guard
- `app/components/mushaf/*` — including the layout/edition picker and the viewing-owner chip
- `app/not-found.tsx` — token check only, if it drifted

## Constraints

- Do not change the grant guard's auth logic, redirect targets, or `getServerSession` usage.
- Never render the owner's name on the access-removed path (ADR 0012).
- The root 404 must keep theme tokens and plain `<a>` links.
- Keep the mushaf-variant UI generic — more print editions are expected.
- This route has **no existing snapshot coverage** — add it. Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not give the borrowed-context chip a state accent — it is identity, not state.
- Do not add the owner's name to the removed-access banner to make it friendlier.
- Do not hard-code the picker for exactly the editions that exist today.
- Do not convert the root 404 to `next/link`.

## Decisions Made

- Borrowed context is identity information and takes the identity accent — the clearest justification for the two-accent grammar outside the reader.
- The edition picker is designed for growth, matching the deliberately generic mushaf-variant schema.

## Implementation notes (2026-08-22)

### A new token family: `--warning`

`AccessRemovedBanner` was painted with raw `amber-*` utilities **plus a `dark:` variant** — a per-theme fork of a single rule, which is exactly what the language forbids, and the last such fork left in the app. There was no alternative token: neither accent may carry "something is wrong" (§5), and `--destructive` is too strong for a recoverable notice.

So `--warning` / `--warning-foreground` were added to all three theme blocks and to `tailwind.config.ts`. This is the "reopen 2.1 rather than patch locally" branch of 4.1's decision tree being taken, not sidestepped.

**Measured and retuned.** The first values gave the warning icon **4.33** on light and **4.41** on gold against the flattened `bg-warning/10` surface — both under AA. Darkened to `32 74% 29%` and `30 72% 27%`, which measure **5.35 / 5.50 / 8.43** across light / gold / dark. Worth noting the flattening step: the banner fill is a 10% wash, so contrast has to be computed against the *composited* surface, not against the token.

`--warning-foreground` is declared but not yet consumed — it exists so a future solid `bg-warning` chip has its pair, and so no theme block is missing a member of the family.

### Borrowed context is the grammar's clearest case

The "Mushafs I can access" rows now use identity throughout: the open affordance, the hover border, and the person avatar. Nothing on that surface is live — it says *whose* mushaf this is, which is the one thing gold exists for. This is the demonstration the plan predicted, and it reads correctly precisely because nothing competes with it.

### Accent-grammar corrections

| Element | Was | Now | Why |
|---|---|---|---|
| `SectionCard` icon chip | `bg-primary/10 text-primary` | identity warm | What the section is. |
| `SectionCard` hero inner frame | `border-primary/20` | `border-gold/25` | It is ornament, and ornament is identity. |
| `AccessibleMushafList` "Open" + hover border | `text-primary`, `hover:border-primary/40` | identity | Borrowed context, above. |
| `PersonAvatar` | `bg-accent` / `text-accent-foreground` | neutral well | Same fix as the account avatar in 3.2 — `--accent` is the state accent's family. |
| Generated access code panel | `border-primary/30 bg-primary/5` | hairline + well fill | A code is a **value the user reads and copies** — evidence, not a control. The copy action beside it keeps the accent, because that one does something. |
| Hub + 404 title flanks | `◆` glyph, `text-primary` | `.fq-ornament`, identity | Drawn, not typed. |
| Revoke / regenerate controls | `hover:bg-accent` | inert well treatment | Secondary controls read as one dimmed group. |

`MushafLayoutRow`'s selected-edition tick keeps `--primary`: a selected edition **is** state. It was left alone deliberately.

### Picker built for growth

`MushafLayoutSection` was the last block in the settings sheet still carrying its own `<h3>` and `bg-muted` slab. It now uses the shared `SettingsSection`, and its edition rows are `fq-section-row`s inside that one group — so however many editions are registered, they read as rows of one surface rather than a stack of cards. Nothing is sized for exactly the two that exist today.

### Constraints honoured

- Grant guard auth logic, redirect targets and `getServerSession` usage: untouched.
- The removed-access banner stays generic — no owner name (ADR 0012) — and takes neither accent.
- The root 404 keeps plain `<a>` links; only tokens and the ornament changed.

### Not verified here

The hub's signed-in body (generate/redeem cards, viewer lists, the removed banner) needs a session and could not be exercised headlessly. Tokens and the banner's contrast were verified by injecting its real markup into the live page in all three themes; structure was verified by reading the rendered class output. **This route still has no snapshot coverage** — the plan asked for it to be added, and that has not been done, because baselines are CI-generated for this programme and adding a spec without a baseline run would land a failing test. It should go in with the `workflow_dispatch` regeneration before the PR merges.
