# 4.4 — Mushaf hub and shared-grant surfaces

**Type:** feature
**Date:** 2026-08-21
**Status:** ready-to-implement
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Migrate `/mushaf` (the hub) and the shared-grant surfaces at `/mushaf/[grant]/pages/[id]` — the layout guard's redirect states, the "viewing someone else's mushaf" chrome, and the access-removed banner. Also the mushaf-layout selection UI, which is where a user picks a print edition.

## Approach

This screen carries two things the rest of the app does not:

1. **A borrowed-context state.** When viewing another user's mushaf, the app must say so persistently without competing with the reading surface. Under the two-accent grammar this is *identity* information — whose mushaf this is — which is exactly the role gold now carries. That makes this the cleanest demonstration of why the language needed two accents.
2. **Privacy-constrained copy.** ADR 0012 forbids showing the owner's name on the access-removed path; the banner is deliberately generic. The visual treatment must not imply more identity than the copy is allowed to carry.

The mushaf-layout picker is a selection surface over print editions and is likely to gain more options later — the schema was kept generic for exactly that. Design it to hold more than two entries.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| Element states whose mushaf is being viewed | Identity accent. |
| Element states a live/selected edition | `--primary`. |
| Access was removed | Generic banner; no owner name, no identity treatment implying one (ADR 0012). |
| Layout picker gains entries | Must hold more than two without redesign. |
| An unauthenticated or revoked user arrives | `redirect()`, not `notFound()` — behaviour unchanged. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| `/mushaf` hub, three themes, both locales | New language; edition picker legible and holds >2 entries. |
| Viewing a granted mushaf | Borrowed-context chrome present and persistent, not competing with the page. |
| Access revoked → `/mushaf?removed=1` | Generic banner, no owner name, correct redirect. |
| Unauthenticated on a grant route | Redirects to locale home. |
| Root 404 | Still uses theme tokens and plain `<a>` links — a `next/link` client-nav from the root 404 can paint before the locale tree's CSS chunk loads in prod. |
| Mobile, tablet, desktop | Hub composition holds at every band. |

## Files to Change

- `app/[locale]/mushaf/page.tsx`
- `app/[locale]/mushaf/[grant]/pages/[id]/page.tsx` and its layout guard
- `app/components/mushaf/*` — including the layout/edition picker and the viewing-owner chip
- `app/not-found.tsx` — token check only, if it drifted

## Constraints

- Do not change the grant guard's auth logic, redirect targets, or `getServerSession` usage.
- Never render the owner's name on the access-removed path (ADR 0012).
- The root 404 must keep theme tokens and plain `<a>` links.
- Keep the mushaf-variant UI generic — more print editions are expected.
- This route has **no existing snapshot coverage** — add it. Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not give the borrowed-context chip a state accent — it is identity, not state.
- Do not add the owner's name to the removed-access banner to make it friendlier.
- Do not hard-code the picker for exactly the editions that exist today.
- Do not convert the root 404 to `next/link`.

## Decisions Made

- Borrowed context is identity information and takes the identity accent — the clearest justification for the two-accent grammar outside the reader.
- The edition picker is designed for growth, matching the deliberately generic mushaf-variant schema.
