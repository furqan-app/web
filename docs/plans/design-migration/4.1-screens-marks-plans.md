# 4.1 — Marks and plans screens

**Type:** feature
**Date:** 2026-08-21
**Status:** implemented
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

## Summary

Migrate `/marks` and `/plans` to the new language. These go first in Phase 4 deliberately: they are the lowest-risk screens in the app — list-and-detail surfaces with no mushaf rendering, no font contract, no reader invariants — which makes them the honest end-to-end test of whether the token layer and primitives actually carry the language without per-screen work.

## Approach

The measure of success here is **how little code this subtask writes.** If Phases 2 and 3 did their job, most of the change is deleting local overrides — bespoke shadows, one-off borders, hand-rolled focus rings, ad-hoc card padding — and letting tokens and primitives show through. A large diff here is a signal that 2.1 or 3.1 left gaps, and the right response is to reopen those, not to patch locally.

The lab's settings panel is the structural reference: grouped sections with hairline rows and gold overlines, rather than stacks of identical floating cards. Both of these screens are list surfaces and should adopt it.

Watch the empty and loading states — list screens are where those actually matter, and the lab never designed either.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| A local override duplicates a token | Delete the override. |
| A local override contradicts a token | Delete it, and check whether the token is wrong for everyone. |
| The screen needs something tokens do not provide | Reopen 2.1. Do not add a literal. |
| A card exists only to separate rows | Replace with a grouped section and hairlines. |
| A card carries a distinct object | Keep it as a card. |
| Empty or loading state is undesigned | Design it here, against the language, and record it for 0.4's spec to absorb. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| `/marks` with marks, three themes, both locales | Renders in the new language; no local colour literals remain. |
| `/marks` empty | Designed empty state, not a bare page. |
| `/marks` paginated | Pagination controls in the new language; behaviour unchanged (`paginate-my-marks.md`). |
| `/plans`, three themes | Same. |
| Mobile and tablet | Both screens hold at every band. |

## Files to Change

- `app/[locale]/marks/page.tsx` and `app/components/marks/*`
- `app/[locale]/plans/page.tsx` and `app/components/plans/*`
- `app/components/MarkModal.tsx`, `MarkerColorPicker.tsx` if they carry local styling

## Constraints

- Consume tokens and primitives; add no colour literals.
- Do not change data fetching, pagination behaviour, or auth gating — this is a visual migration.
- `app/[locale]/marks/page.tsx` carries an uncommitted padding edit from superseded in-flight work; default disposition is revert, not preserve.
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not patch around a token gap locally — reopen 2.1.
- Do not redesign the information architecture of either screen; this is a language migration, not a UX rework.
- Do not skip the empty states because the happy path looks right.

## Decisions Made

- These two screens go first as the end-to-end proof of the token and primitive layers.
- A large diff here is treated as evidence of a gap upstream, not as expected work.
- Empty and loading states are designed here and fed back into the language spec.

## Implementation notes (2026-08-22)

**The diff-size test passed, with one honest exception.** Almost all of the work was deleting local overrides — four hardcoded `rgba` panel casts, three stock `ring-offset-background` focus rings, and the `--primary` misuses below. The exception is `.fq-ornament`, a genuinely new primitive: 2.1 shipped the identity *tokens* but nothing that draws with them, so the `◆` glyph had no token-level replacement to inherit. That is a gap in 3.1's scope, recorded rather than patched around — the rule lives in `globals.css` with the other primitives, not in either screen.

### Accent-grammar corrections found on these screens

| Element | Was | Now | Why |
|---|---|---|---|
| Page title flanks (both screens) | `◆` glyph, `text-primary` | `.fq-ornament`, identity | Ornament is drawn, not typed, and is identity in every theme (§7). |
| Marks surah group heading | `text-primary`, bold | overline treatment, `text-gold` | Which surah you are looking at is *where you are* — identity. |
| Mark comment badge | `border-primary/30 bg-primary/5`, primary icon | hairline + well fill, inert icon | A comment is content. This put the state accent on every row that happened to have a note. |
| Plan template icon | `bg-primary/10 text-primary` | `bg-gold/12 text-gold` | *What kind* of plan this is — identity. It was tinting abandoned plans with the live accent. |
| Plan status label | always `text-muted-foreground` | `text-primary` when active | Whether it is running **is** state, and that is where the accent belongs. One accent per element. |
| Signed-out prompt icon (both) | `bg-primary/10 text-primary` | identity warm | The sign-in button is the one live control; the icon is identity. Never both. |
| Marks filter chips | inert on `--muted` | inert on `--well` | The unselected filters now read as one dimmed group; the selected one keeps `--primary`, which is correct — selected is state. |

### Structure

Marks rows were a stack of identical `rounded-xl border bg-card` cards — one competing object per mark. They are now hairline-separated `.fq-section-row`s inside one `.fq-section-group` per surah. Plan cards stayed cards: a plan is a distinct object the user edits, pauses and abandons, which is exactly the decision tree's "card carries a distinct object" branch.

### Empty and loading states

Both screens' empty states were a bare centred sentence. They now use a section-group surface with an inert icon, a title and a hint (`marks.emptyHint`, `plans.emptyHint`, added to both locales). Skeletons were restructured to mirror the real row shape inside the same surface, so the layout does not reflow the moment data lands.

### One defect worth recording

**`position: sticky` is trapped by an `overflow: hidden` ancestor.** `.fq-section-group` clips rows to its radius with `overflow: hidden`, which makes it a scroll container — so the marks surah heading stuck to the *group's* content box (i.e. never moved) instead of the viewport, silently losing behaviour that worked before the migration. Fixed with a `.fq-section-group-open` modifier that opts out of the clip; the first and last rows carry no background of their own, so nothing overflows the radius anyway. Verified by scrolling a real container and comparing the heading's box before and after: held in all three themes.

`.fq-ornament` also needed an explicit `display: inline-block` — as a bare `<span>` it is inline, ignores `width`/`height`, and collapses to zero anywhere its parent is not a flex container. It rendered correctly on both page headers (flex parents) and measured **0px** the moment it was probed outside one.

### Verified

- No page errors on `/en/marks` or `/en/plans`, light and dark.
- Primitives sampled as *computed* values in all three themes: group `overflow: visible`, heading `position: sticky` and holding, row hairline 1px, overline and heading resolving to identity bronze/gold (`rgb(133,97,50)` / `rgb(116,82,37)` / `rgb(207,164,84)`), `--panel-cast` resolving per theme.
- Signed-out path screenshotted in both themes; the drawn ornament, the identity icon and the single emerald live control all read correctly.

### Not verified here

The signed-in list bodies could not be exercised — the headless probe has no session. Structure, tokens and the sticky fix were verified by injecting the real markup into a live page in all three themes instead. Pagination, filtering and delete behaviour were not touched.
