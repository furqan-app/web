# 3.1 — UI primitives

## Summary

Reshape the twelve primitives in `components/ui/` to the new language. These are the highest-leverage files in the programme: every one of the eight routes is built from them, so the visual change per file touched is at its maximum here and the screen subtasks in Phase 4 shrink to mostly deleting local overrides.

## Approach

The twelve: `button`, `command`, `dialog`, `dropdown-menu`, `input`, `popover`, `radio-group`, `sheet`, `slider`, `switch`, `tabs`, `textarea`.

Work them in dependency order, because several compose: `button` → `input`/`textarea` → `switch`/`radio-group`/`slider` → `popover`/`dropdown-menu` → `dialog`/`sheet` → `command`/`tabs`.

Three things change in each:

1. **Surface and depth** — the elevation ladder from 2.1 replaces per-component shadow literals.
2. **Control hierarchy** — the inert-vs-live treatment, and the shared focus ring, replacing each component's own focus styling.
3. **Accent role** — every accent use gets classified by the 0.4 accent test. Most primitives express *state*, so most stay on `--primary`; identity uses are rarer and deliberate.

The lab already proved the sheet: its settings panel is a working reference for grouped sections, hairline rows, overline headers, and the inert-vs-live split. Port that treatment into `sheet.tsx` rather than re-deriving it.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| Component hard-codes a shadow | Replace with the elevation ladder token. |
| Component has its own focus ring | Replace with the shared ring. |
| Component uses an accent | Classify with the 0.4 accent test; most resolve to state/`--primary`. |
| Component has a `dark:` variant doing a fork | Check whether the token now handles it. Prefer deleting the fork. |
| Component uses `animate-in` / `fade-in-0` etc. | These are inert no-ops — `tailwindcss-animate` is not installed. Use Radix `data-[state=*]` with `transition-*`. |
| A primitive needs a new token | Stop. Tokens are 2.1's job; reopen it rather than adding a literal here. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| Each primitive, three themes | Renders correctly; no token falls back to unset. |
| Each primitive, RTL and LTR | Mirrors correctly; `start`/`end` logical properties, not `left`/`right`. |
| Keyboard focus on every interactive primitive | Visible shared focus ring; ring clears contrast against its own surface in all three themes. |
| `sheet` with a long body | Header and footer hold; body scrolls; no clipped bottom (the failure mode in `fix-sidebar-bottom-clip.md`). |
| `dialog` | Has a description, or is explicitly exempted — the Radix warning in `fix-dialog-missing-description.md` must not return. |
| Reduced motion | Every transition respects `motion-reduce:`. |

**Result — all twelve done; 3 themes x 2 directions all clear.** No stock ring, no `ring-offset-background`, and no `shadow-sm/md/lg` literal remains anywhere in `components/ui/`. The shared focus ring resolves and clears the 3:1 non-text floor against its own gap colour in every theme (light 4.51, gold 5.88, dark 3.65). Sheet opens with a real panel cast and its bottom is not clipped; no Radix description warning; no console errors. `tsc` clean, lint unchanged at the two inherited files.

## Findings

**1. `shadow-[var(--panel-cast)]` silently rendered nothing.** Tailwind cannot type-infer a bare `var()` inside `shadow-[…]` — it resolved the value as a shadow *colour*, left `--tw-shadow` at its `0 0 #0000` default, and every panel rendered with no shadow while the class sat in the markup looking correct. Caught by sampling the computed `boxShadow`, not by reading the class list. Replaced with a named `.fq-panel-cast` utility, which is also clearer about what it is. `shadow-[shadow:var(--panel-cast)]` would work too.

**2. The stock focus ring was structurally broken on every floating surface.** `ring-offset-2 ring-offset-background` draws the ring's gap in `--background` — correct only on the page background, and wrong on every dialog, sheet, popover, dropdown and nav bar, which are not that colour. The shared ring takes its gap from `--chrome` instead. This was a real defect, not a restyle.

**3. Three no-op animation clusters were doing nothing at all.** `animate-in`, `fade-in-0`, `zoom-in-95` and `slide-in-from-*` need `tailwindcss-animate`, which is not installed, so `sheet`, `popover` and `dropdown-menu` had no enter or exit motion despite carrying the classes. Replaced with real `transition-*` on Radix `data-[state]`. Note the exit transition still will not play: Radix `Presence` defers unmount for CSS *animations*, not transitions, so a closing element unmounts immediately. That matches the behaviour `dialog.tsx` already shipped, and adding the dependency is explicitly out of scope.

**4. Thumb and active-tab shadows were removed rather than tokenised.** A switch thumb, a slider thumb and an active tab are not panels, and a panel-weight cast on a 20px thumb is wrong. On dark a drop shadow there produces no pixels at all (ADR 0032), so the honest fix is to let the face and border carry the lift, which they already do. The active tab took a border instead.

**5. Destructive is fixed, closing 2.1's handover.** Both pairs now clear AA in all three themes — foreground-on-destructive 4.90 / 4.85 / 5.42, and destructive-as-text-on-card 4.90 / 4.56 / 5.05. Light and gold darkened `--destructive`; **dark moved the foreground instead**, because its red doubles as `text-destructive` on near-black cards and darkening it to 50% fell to 3.65:1 there. Same shape as the `--primary`/`--accent-foreground` split that block already documents: when one lightness cannot serve both pairs, move the other side of the pair.

**Still open:** dark's `--primary` as text on `--background`/`--card` (3.74 / 3.48). Unchanged, and deliberately so — the migration should dissolve it rather than solve it, because ornament and metadata move to `--gold` and `--primary` stops being text. Phase 4 must confirm that rather than assume it.

## Files to Change

- `components/ui/*.tsx` — all twelve.
- `app/globals.css` — only if a shared primitive rule genuinely belongs there rather than in the component.

## Constraints

- Consume 2.1's tokens. No new colour literals in components.
- `start`/`end` logical properties throughout.
- `tailwindcss-animate` is not installed — `animate-in`/`fade-in-*`/`slide-in-from-*` are no-ops. Use Radix state attributes with `transition-*`.
- Respect `prefers-reduced-motion` via the `motion-reduce:` variant.
- Do not change any primitive's public API — 81 components consume these.
- Baselines are regenerated only via the `workflow_dispatch` CI job, targeting the migration branch — never by committing local PNGs (font/anti-aliasing drift between local and CI).

## What NOT to Do

- Do not introduce a new token here. If one is missing, reopen 2.1.
- Do not change component props or variant names.
- Do not add `tailwindcss-animate` to make the no-op classes work — that is a separate decision with its own bundle cost.
- Do not fix a screen-specific problem inside a primitive; that belongs to its Phase 4 subtask.

## Decisions Made

- Dependency order, not alphabetical — composing primitives inherit from their parts.
- The lab's settings sheet is the reference implementation for `sheet.tsx`, ported rather than re-derived.
- Primitives mostly express state, so most accent uses stay on `--primary`; identity uses are the exception and are justified individually. In practice every accent in the twelve resolved to state — a radio's selection, a switch's on, a slider's filled range, an active tab — so no primitive took the identity accent. Identity appears in these files only via `.fq-overline`, which is a shared rule, not a primitive.
- Shared rules live in `globals.css`, not duplicated per component: one focus ring, one panel cast, one grouped-section treatment. A ring re-declared twelve times drifts twelve ways, which is what had already started to happen.
- Never `shadow-[var(--token)]`. Use a named utility — Tailwind's type inference silently turns the arbitrary form into a shadow colour.
