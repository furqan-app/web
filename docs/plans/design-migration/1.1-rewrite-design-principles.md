# 1.1 — Rewrite the canon

**Type:** feature
**Date:** 2026-08-21
**Status:** implemented, with one plan defect resolved — see Addendum
**Parent:** [INDEX.md](INDEX.md) · **Issue:** #360 · **ADR:** [0047](../../architecture/adr/0047-adopt-reader-lab-design-language.md)

> Note (#494, 2026-09-02): the `/impeccable` review gate and `/impeccable document` regeneration
> described below no longer exist. `DESIGN.md` is hand-maintained; design-language alignment is a
> manual review concern (`docs/plans/remove-workflow-skills.md`). This record is otherwise unchanged.

## Summary

Rewrite `docs/design/design-principles.md` to the new language and regenerate root `DESIGN.md`. This must land before any token or component work: `DESIGN.md` is what `/impeccable` reads, and ADR 0041 wires `/impeccable` into plan → implement → review. Migrating code against a stale canon means every subsequent task is reviewed against the language being replaced, and the review gate spends the whole programme pushing work backwards.

## Approach

`design-principles.md` currently states four rules the new language contradicts outright:

| Current rule | Replacement |
|---|---|
| "Never reach for a second accent colour; one is enough" — `text-primary` as the single unifying ornament | The two-accent grammar: gold for identity/metadata/ornament, primary for live state only |
| `◆` diamond separators as `text-[6px] text-primary` glyphs | Drawn ornament — hairline rules tapering to an open diamond, in gold |
| Navigation buttons `w-[52px] h-[52px]`, `bg-card border border-border shadow-sm` | The derived control geometry from `design-language.md` |
| Preferred shadow `0_2px_8px / 0_16px_48px-16px` | The shared depth ladder; dark carries lift with face-and-rim, not shadow |

Rewrite it as a distillation of `design-language.md` (0.4) — principles a reader applies, with the full derivation living in the language spec. Keep the sections that are still true (lucide-only icons, stroke weights, ornaments are `pointer-events-none` in a high z-index layer) rather than rewriting the file wholesale.

Then regenerate `DESIGN.md` via `/impeccable document` — never hand-edit it — and verify the gate agrees with the new language.

## Decision Tree / Algorithm

| Condition | Action |
|---|---|
| A current principle contradicts the new language | Replace it, and record the supersede in `Decisions Made`. |
| A current principle is orthogonal (icon library, stroke weight, pointer-events) | Keep verbatim. |
| A principle exists only in the lab and not in `design-language.md` | It was never derived. Do not add it here. |
| `DESIGN.md` and `design-principles.md` disagree after the rewrite | Regeneration was skipped. Re-run `/impeccable document`. |

## Verified Test Cases

| Case | Required outcome |
|---|---|
| `/impeccable critique` on a migrated lab component | Returns no finding that contradicts the new language. |
| `/impeccable critique` on an unmigrated production component | Findings now point *toward* the new language, i.e. the gate has become a migration aid. |
| A future task reads only `design-principles.md` | Can build a correct new-language component without seeing the lab. |
| `DESIGN.md` diff | Regenerated, not hand-edited. |

## Files to Change

- `docs/design/design-principles.md` — rewritten to the new language.
- `DESIGN.md` (repo root) — regenerated via `/impeccable document`.
- `docs/standards/styling.md` — cross-reference to `design-language.md`; token contract itself is updated in 2.1, not here.

## Constraints

- Must land before subtask 2.1 opens.
- `DESIGN.md` is generated. Regenerate it; never hand-edit.
- Keep principles that remain true rather than rewriting the file wholesale — an unnecessary rewrite loses recorded reasoning.
- No code changes in this subtask. Documentation only, so it is reviewable on its own.

## What NOT to Do

- Do not hand-edit `DESIGN.md`.
- Do not add principles that 0.4 did not derive.
- Do not delete the "Process" section pointing at `/frontend-design` — it stays, now grounded in the new language.
- Do not soften the accent-grammar rewrite to avoid conflicting with the old one. ADR 0047 already superseded it; a hedged canon leaves the gate ambiguous.

## Addendum — the regeneration step could not run as written (2026-08-21)

The plan says: rewrite `design-principles.md`, then regenerate `DESIGN.md` via `/impeccable document`. That step is impossible at this point in the programme, and the plan did not notice.

`/impeccable document` **generates `DESIGN.md` from project code**, not from `design-principles.md`. Production code is still old-language — that is what phases 2–5 exist to change — so running it now would faithfully re-extract the design being replaced. ADR 0041 also lists `document` among the Build/Iterate commands excluded from what a task may execute, and the skill's own reference requires stopping to ask before overwriting an existing `DESIGN.md`.

Both branches were blocked: regenerating produces the wrong answer, and leaving the file alone means `context.mjs` feeds the superseded rules to every phase 2–5 critique — the exact failure this subtask exists to prevent.

**Resolved with the user:** a short, clearly-marked banner was hand-added at the top of `DESIGN.md`. It restates no design, edits nothing below it, points at the new canon, and tables the five rules that must not be enforced in review. `DESIGN.md` is regenerated properly — and the banner deleted — once 2.1 lands the token layer and a code scan can tell the truth.

**For future plans:** "regenerate the generated file" is only a valid step when the generator's input is already correct. In a migration the canon leads the code by several phases, so the generated artifact is stale *by construction* for the whole middle of the programme.

## Decisions Made

- Canon before code, because ADR 0041 makes the canon an enforcement mechanism, not just reference material.
- `DESIGN.md` carries a hand-added supersede banner for the duration of the migration, and is regenerated after 2.1. A stale gate was judged worse than one deliberate, non-substantive hand-edit of a generated file.
- `styling.md`'s gold-aliasing rule is marked as migrating rather than rewritten — its token contract belongs to 2.1.
- The one-accent rule, the glyph separators, the 52px nav button geometry, and the preferred-shadow value are all superseded by ADR 0047.
- Documentation-only subtask, deliberately separate from 0.4, so the derivation and the canon rewrite are reviewed independently.
